# 회사 문서 작성 (신규 · 재생성 공통)

## 언제 쓰나

- 신규: "<회사명> 문서 만들어줘", "<회사명> 커버리지 시작하자"
- 재생성: "<회사명> 문서 개선해줘 / 업데이트해줘 / 최신화해줘 / 템플릿 기준으로 다시 봐줘"
- **대상 아님**: 거시지표 → `create-macro-doc` · `AGENTS.md`·`authoring-guide.md` 자체 검토 → `review-master-docs`

## 왜 재생성인가

기존 폴더를 부분 수정하면 눈에 띄는 절만 고치고 넘어가게 되고, 템플릿이 바뀐 뒤에도 옛 절 구성·옛 항목 수가 그대로 남는다. 그래서 **개선 요청도 재생성으로 처리한다** — 폴더를 지우고 현재 템플릿으로 새로 만들면 구조가 항상 최신이고, 모든 수치를 다시 검증하게 된다. 지운 내용은 git 히스토리에 남으므로 영구 손실은 아니다.

---

## 한 세션에서 끝낸다

**회사 폴더 하나는 한 대화에서 처음부터 끝까지 만든다.** 중간에 세션을 끊거나 사용자에게 "다음 단계를 새 세션에서 시작하라"고 안내하지 않는다.

한때 이 스킬은 작업을 5개 세션으로 쪼개게 했다. 세션당 컨텍스트를 낮추는 효과는 실제로 있었지만, **Rocket Lab을 5단계로 만든 결과 5시간 한도의 80% 이상을 여전히 썼다** — 세션을 오갈 때마다 시스템 프롬프트·`AGENTS.md`·툴 스키마·앞 단계 산출물을 다시 적재하는 비용이 절감분을 상당 부분 되먹었고, 사람이 터미널을 5번 왕복하는 운영 부담은 그대로였다. 그래서 분할은 폐기한다.

**대신 아래 "턴을 낭비하지 않는 법"이 유일한 절감 수단이 된다.** 한 세션으로 합친 만큼 후반 턴이 비싸지므로, 이건 예전보다 더 엄격히 지킨다.

작업 순서와 턴 예산(총 ≤50턴 목표):

| 순서 | 만드는 것 | 턴 예산 |
|---|---|---|
| 1 | 폴더 준비 (carryover 추출 · 템플릿 복사) | ≤6 |
| 2 | `04_metrics.md` | ≤12 |
| 3 | 정성 조사 → `01`·`02`·`03`·`05`·`08` | ≤14 |
| 4 | `06`·`07` | ≤8 |
| 5 | `09`·`10`·`11` + 마무리 검증 | ≤10 |

예산을 넘길 것 같으면 **작업을 줄이지 말고 묶는 단위를 키운다.**

### 중단됐다 재개할 때

세션이 죽었으면 처음부터 다시 하지 말고 어디까지 됐는지부터 본다. 템플릿 파일에는 `> ⚠️` 지침 블록이 반드시 남아 있고(파일당 2개 이상), 다 채운 파일에는 하나도 없다. **한 콜로 판정한다**:

```bash
grep -l '^> ⚠️' docs/sectors/<sector>/<company>/*.md 2>/dev/null | sed 's#.*/##' | tr '\n' ' '
```

걸리는 파일이 곧 남은 일이다. **이미 채운 문서를 다시 읽어 검토하지 않는다** — 필요한 값만 `grep`/`sed -n`으로 뽑아 쓴다.

---

## 턴을 낭비하지 않는 법

비용은 대략 `턴 수 × 그 시점의 컨텍스트`의 합이다. 턴 하나는 그 시점 컨텍스트 전체를 다시 실어 나르므로, **세션 후반의 턴 하나는 초반의 다섯 배쯤 비싸다.** 실측에서 나온 사실 셋이 아래 규칙을 만들었다.

- 모델이 써낸 **문서 분량은 전체 비용의 1% 미만**이다 — 문서를 짧게 써서 절약할 수 있는 건 없다.
- **출력의 66~79%가 사고(thinking)**였고, 그 사고는 상위 5개 턴에 절반 이상이 몰렸다.
- **도구 결과는 세션당 60~110KB(≈30k 토큰)뿐**이다. 조사 원문을 줄이는 건 이미 한계다 — 남은 건 턴 수를 줄이는 것뿐이다.

### 독립적인 호출은 반드시 한 턴에 몰아서 낸다

**실측(Synopsys): 51개 도구 호출에 52턴 — 병렬 호출이 단 한 건도 없었다.** 서로 결과를 기다릴 필요가 없는 호출을 따로따로 낸 것이 그 세션 턴 수의 대부분을 만들었다. 다음은 전부 **한 턴에** 낸다:

- **웹 조사**: 검색어 4~5개, 페이지 3~4개를 한 턴에 같이 던진다. 결과를 보고 다음 검색어를 정해야 하는 경우만 턴을 나눈다.
- **파일 읽기**: `sed -n`/`cat`을 `echo` 구분자와 함께 하나의 `bash` 명령으로 잇는다.
- **문서 쓰기**: heredoc 여러 개를 한 명령에 이어 붙인다. 파일 5개를 쓴다고 5턴 쓰지 않는다.
- **검증**: 마무리 체크리스트의 `grep`·`mkdocs build`는 전부 한 콜.

### 그 밖에

- **1차 공시 재무 수치는 스크립트로 한 번에 가져온다.** 아래 2-1 참고. 10-K HTML을 내려받아 `grep`으로 캐는 방식은 쓰지 않는다(한 세션에서 같은 `10k.txt`에 86회 접근한 실측이 있다).
- **쓰기는 수치 검증이 끝난 뒤 한 번에 한다.** 가장 비쌌던 건 문서를 먼저 쓰고 나중에 `sed -i`로 깁던 수정 라운드였다 — 컨텍스트가 커진 시점에 한 줄 고치는 게 제일 비싸다. 값이 확정되지 않았으면 쓰지 말고, 확정됐으면 heredoc 한 번으로 끝낸다.
- **스크립트 산출물을 대화로 통과시키지 않는다.** `gen_technical_chart.py`의 SVG는 수만 자다. 반드시 파일로 리다이렉트하고 스크립트로 삽입한다(5-1 참고). 조사·산출 원문은 `.work/<company>/`에 내리고 대화로는 필요한 줄만 올린다.
- **파일을 통째로 `cat` 하지 않는다.** 실측에서 `cat 04_metrics.md` 한 콜이 18KB(≈6k 토큰)를 세 번째 턴에 밀어 넣었고, 그게 남은 49턴 내내 다시 실려 **그 세션 비용의 약 3%**를 혼자 썼다.
- **긴 사고는 판단이 걸린 구간에만 쓴다.** 방법론 채택 여부(4-2)·Bear Case 3요소 판정(4-3)·GAAP 정의 판별(2-2)이 그 구간이다. 조사 결과를 정해진 틀에 옮기는 작업(`01`·`02`·`03`·`05`·`08`·`11`)에서는 길게 생각해도 품질이 안 올라간다.

### 서브에이전트에 조사를 통째로 넘기지 않는다

한때 이 스킬은 "웹 조사를 서브에이전트에 위임하면 원문이 본 세션에 안 쌓인다"고 지시했다. **실측 결과 틀렸다.** EQT에서 서브에이전트 2개가 252콜을 돌며 본 세션(16.5M)보다 많은 22.1M의 컨텍스트를 쌓았다. 정성 조사 에이전트 하나가 154턴 동안 Bash를 89번 부르며 예전에 본 세션이 하던 `10k.txt` 파헤치기를 그대로 반복했다. 조사 루프를 옮기면 그 루프의 컨텍스트도 같이 따라가고, 게다가 서브에이전트는 부모와 프롬프트 캐시를 공유하지 못해 시스템 프롬프트·`AGENTS.md`·툴 스키마를 새로 적재한다. **긴 대화 하나가 콜드 스타트 루프 둘보다 싸다.**

## 1. 폴더 준비

### 1-1. 재생성이면, 지우기 전에 옮길 것부터 추린다

기존 폴더가 있으면 **먼저 읽고**, 웹에서 다시 못 구하는 항목만 메모해 둔다. 그 외에는 전부 새로 조사한다. 읽기는 한 콜에 묶는다.

- `08_news.md` 로그 (발생 시점과 그때의 판단 기록)
- `04_metrics.md`의 `!!! warning` — 이 회사 고유의 오독 위험(분할 소급조정 이력, 일회성 손익, 짧은 상장 이력)
- `04_metrics.md` C절의 사업 고유 지표 목록과 정의 — **섹터 단위로 합의된 값**이라 임의로 바꾸면 같은 섹터 회사와 비교가 깨진다
- `06_valuation.md`의 방법론 채택·제외 사유와 가중치 근거

추린 내용은 **폴더를 지우기 전에 `mkdir -p .work/<company>` 후 `.work/<company>/carryover.md`에 저장한다.** 세션이 죽어도 남고, 5-3에서 반영 여부를 확인한다.

### 1-2. 폴더 삭제 후 템플릿 복사

```bash
mkdir -p .work/<company>
rm -rf docs/sectors/<sector>/<company>
cp -r docs/.template/company docs/sectors/<sector>/<company>
```

신규 섹터라면 폴더명은 풀어 쓴 소문자 스네이크케이스(`electronic_design_automation`), 회사 폴더명은 회사명 스네이크케이스(`synopsys`). 복합기업은 매출 비중이 아니라 **"이 저장소에서 그 회사를 보는 이유"가 되는 사업** 기준으로 섹터를 정한다. 섹터 폴더가 새로 생기면 `docs/sectors/.pages`에 등록한다(안 하면 경고 없이 내비게이션에서 빠진다). **섹터 폴더에 산업 분석·개요 문서를 두지 않는다** — 산업 분석은 각 회사 `01_overview.md`의 "산업 / 시장 내 위치"에서 그 회사 관점으로만 다룬다. 유일한 예외가 섹터 전용 용어를 모으는 `00_glossary.md`인데, 이건 **정의만** 담고 분석·전망은 담지 않는다(2-3 참고).

## 2. `04_metrics.md` — 이후 모든 문서가 인용하는 단일 출처

### 2-1. GAAP 수치를 스크립트로 먼저 확보한다

A절·B절의 뼈대는 **SEC가 회사로부터 XBRL로 받아둔 값**으로 채운다. 10-K를 텍스트로 바꿔 훑지 않는다.

```bash
uv run python scripts/fetch_sec_facts.py <TICKER> --emit all -o .work/<company>/facts_sec.md
sed -n '1,80p' .work/<company>/facts_sec.md    # 표는 80줄 안쪽이므로 한 번에 읽어도 된다
```

- 셀별 원공시(form·제출일·accession)가 필요하면 `--emit sources`. 소급 수정된 값에는 `*`, 파생값(Q4 = FY − Q1·Q2·Q3, 이자부 차입금 합계)에는 `ᵈ`가 붙는다 — **파생값을 인용할 땐 문서에도 파생임을 밝힌다.**
- 이 스크립트는 **지배주주 귀속 vs 연결(NCI 포함)**, **부채총계 vs 이자부 차입금**을 각각 별도 행으로 준다. 이 저장소가 반복해서 틀리던 지점이므로 행을 합치지 말 것.
- 여기서 나오는 값은 **전부 GAAP이다.** Adjusted EBITDA·Adjusted EPS 같은 Non-GAAP은 XBRL에 없으므로 8-K Ex-99 실적발표에서 따로 확인하고 라벨을 붙인다.
- `—`는 "값이 없음"이 아니라 "그 태그로 태깅하지 않음"이다. 결론을 좌우하는 항목이 `—`로 비면 그때만 공시 원문을 확인한다.
- 스크립트가 못 주는 것: 종가·시가총액·베타·컨센서스·가이던스·사업 고유 지표(생산량·매장량 등). 이건 조사해야 하는데, **뒤에 나올 정성 조사(3-1)와 같은 턴에 묶어 던진다** — 같은 회사에 두 번 검색을 나눠 낼 이유가 없다.

### 2-2. 표를 채운다

A(연간)·B(분기)·C(사업 고유)·D(판단 메모) 순으로 채운다. **표 전체를 한 번의 heredoc으로 쓴다.**

- **수치는 기억으로 단정하지 않는다.** 확인 못 한 값은 (E) + 출처 각주.
- 표 기간 안에 주식분할이 있었으면 전 구간(주가·EPS·BPS·DPS·주식수)을 조정 후 기준으로 맞춘다.
- 정의가 불확실하면(GAAP/Non-GAAP, 부채총계 vs 이자부 차입금) "확인 필요"로 남기고 맞다고 가정해 계산에 넣지 않는다.

### 2-3. C절은 섹터 단위로 정한다

같은 섹터에 회사가 이미 있으면 그 지표를 따르고, 첫 회사면 여기서 정한다. 최대 5개. 없는 지표면 용어 문서부터 갱신하되, **두 개 이상의 섹터가 쓰면 `docs/glossary.md`, 이 섹터에서만 쓰면 `docs/sectors/<sector>/00_glossary.md`**에 넣는다(후자가 없으면 만들고 `.pages`도 함께 둔다). 단순한 사업이면 C절을 통째로 삭제하고 사유를 A절 각주에 남긴다.

동종사 문서를 통째로 읽지 말고 **지표명·정의만** 뽑는다(실측: `natural_gas` 5개사 4.6KB ≈ 1.5k 토큰). 아래 명령은 4-1의 가정 대조와 **한 턴에 같이** 낸다:

```bash
S=docs/sectors/<sector>
for f in $S/*/04_metrics.md; do c=$(basename $(dirname $f)); [ "$c" = "<company>" ] && continue
  sed -n '/^## C\. 사업 고유 지표/,/^## D\./p' $f | grep -E '^\||^\*\*이 섹터' \
    | awk -F'|' 'NF>3{print "| "$2"|"$3"|"$4} !/\|/{print}' | grep -v '^| *-\+' \
    | cut -c1-120 | sed "s#^#[$c] #"
done
```

**같은 섹터라도 밸류체인 위치가 다르면 지표도 다르다** — `natural_gas`의 Cheniere(LNG 수출)는 EQT(업스트림 E&P)와 다른 지표를 쓰고, 그 사유를 C절 머리에 적어 뒀다. 무조건 베끼지 말고 **밸류체인 위치가 같은 회사**를 따른다.

## 3. 정성 조사 → `01`·`02`·`03`·`05`·`08`

### 3-1. 무엇을 모으나

`04_metrics.md`가 이미 담은 재무 수치는 **다시 조사하지 않는다.** 여기서 모으는 건 그 표가 못 담는 것이다.

- **연혁**: 회사 방향을 바꾼 전환점(창업·상장·지배구조 변경·매출 구조를 바꾼 M&A·존폐 위기). 월까지 표기, 출처 필수
- **경영진**: CEO 커리어·경영 스타일·보상·지분·차등의결권. 출처는 DEF 14A 우선
- **사업 구조**: 부문별 매출 비중과 그 기준 회계연도(10-K Item 1·7), 지역별 매출
- **경쟁·리스크**: 10-K Item 1A에서 이 회사 고유의 것만. 섹터 공통 리스크는 이 회사에 어떻게 작용하는지까지 써야 남기고, 산업 일반론에 그치면 뺀다
- **밸류에이션 입력값**: 컨센서스 EPS, 베타·WACC·자기자본비용, 최근 종가와 기준일. **집계 사이트끼리 갈리면 한쪽을 고르지 말고 범위로 기록한다**
- **최근 뉴스** 5건 이내와 각각의 출처

**검색·페이지 요청을 한 턴에 4~5개씩 묶어 던진다.** 결과를 보고 다음 질문이 정해지는 경우만 턴을 나눈다. 출처 우선순위는 1차 공시(10-K/10-Q/8-K/DEF 14A) > 회사 IR·실적발표 > 집계 사이트 > 언론. **서브에이전트를 띄우지 않는다.**

조사 원문이 길면 `.work/<company>/`에 내리고 필요한 줄만 대화로 올린다 — 원문이 컨텍스트에 남으면 이후 모든 턴에 다시 실린다.

### 3-2. 다섯 문서를 한 콜의 heredoc 묶음으로 쓴다

조사가 끝나면 **곧바로** 쓴다. 파일당 한 턴씩 쓰지 않는다.

- `05_financials.md`는 **서술형 해석 전용**이다. 표를 새로 만들지 말고 `04`의 값을 인용만 한다. 각 절 3~5문장.
- `08_news.md`: 1-1에서 `carryover.md`로 옮겨둔 기존 로그를 여기서 되살린다.
- `02`·`03`은 3-1에서 모은 연혁·경영진 항목을 그대로 쓴다. 여기서 새로 검색하지 않는다 — 빠진 게 있으면 "확인 필요"로 남기고 넘어간다.

## 4. `06`·`07`

여기가 이 작업에서 **유일하게 진짜 판단이 필요한 구간**이다. 앞뒤 구간에서 아낀 사고 예산을 여기 쓴다.

### 4-1. 같은 섹터에 회사가 이미 있으면 가정을 먼저 대조한다

목표 배수·할인율·가중치가 같은 섹터 안에서 근거 없이 갈리면 두 회사의 적정주가를 나란히 볼 수 없다. **동종사 문서를 통째로 읽지 말고 가정 행만 뽑는다** — 섹터에 회사가 5개여도 1.6k 토큰이면 끝난다(실측: `natural_gas` 5개사 4,727B):

```bash
S=docs/sectors/<sector>
for f in $S/*/06_valuation.md; do c=$(basename $(dirname $f)); [ "$c" = "<company>" ] && continue
  sed -n '/^## 1\. 적용 방법론/,/^## 2\./p' $f | grep -E '^\|' \
    | grep -E '할인율|영구성장률|목표 ?(PER|PBR)|가중치' | cut -c1-160 | sed "s#^#[$c] #"
done
```

- **값을 맞추라는 뜻이 아니다.** 사업 위험이 다르면 Ke도 달라야 한다 — 다만 동종사와 크게 다르면 `06`에 **왜 다른지 한 줄**을 남긴다. 실제로 Kinder Morgan `06`은 Williams와 무위험이자율이 0.03%p 다른 이유까지 각주로 남겼다.
- 무위험이자율은 같은 macro 문서(`rates/treasury_10y.md`)를 쓰되 조회 시점이 다르면 그 날짜를 밝힌다.
- 섹터 첫 회사면 이 절을 건너뛴다.

`04_metrics.md`에서 필요한 절만 한 콜로 가져온다(위 대조 명령과 같은 턴에 낸다):

```bash
D=docs/sectors/<sector>/<company>
sed -n '/^### 2. 밸류에이션 지표/,/^### 3\./p' $D/04_metrics.md
sed -n '/^### 3. 재무 건전성 지표/,/^## B\./p' $D/04_metrics.md
sed -n '/^## D\. 판단 메모/,$p' $D/04_metrics.md
```

### 4-2. `06_valuation.md`

템플릿의 "적용 여부 판단 기준"을 실제로 따진다 — 무배당 기업에 DDM을 쓰지 않고, 고성장 기업에 1단계 DCF를 억지로 쓰지 않는다. 해당 없는 방법론은 왜 뺐는지 명시한다. **할인율과 현금흐름의 짝(Ke↔FCFE, WACC↔FCFF)을 섞지 않는다** — `04` A.4의 FCF는 CFO−CapEx라 FCFE 성격이고 Ke로 할인한다. 1단계 DCF 결론이 다른 방법론과 크게 어긋나면 각주로 넘기지 말고 **가중치를 낮추거나 뺀다.**

### 4-3. `07_investment.md`

Bear Case에 **트리거 / 하방 밸류에이션 / 확인·기각 신호** 셋이 모두 있어야 한다. 이 저장소는 낙관 편향이 기본값이라 여기를 더 엄격히 채운다. 종합 적정주가는 `06`에서 인용하고 여기서 새로 계산하지 않는다.

## 5. `09`·`10`·`11` + 마무리

### 5-1. 차트 (`09`·`10`)

SVG·레벨 표·방법론 수치를 손으로 만들지 않는다 — 커맨드는 `chart-generation-guide.md` "기술적 분석 차트 생성"이 마스터.

**산출물을 대화로 통과시키지 않는다.** SVG는 파일당 수만 자라 한 번 컨텍스트에 들어오면 남은 턴 내내 곱해진다. 일봉·주봉 생성을 **한 콜에** 낸다:

```bash
# 산출물을 파일로 — `-o`를 쓴다.
# `> file 2>&1`로 받으면 스크립트의 경고·완료 메시지가 stderr로 파일에 섞여 문서를 오염시킨다.
W=.work/<company>
uv run python scripts/gen_technical_chart.py <TICKER> --name "<이름>" \
  --close-on <YYYY-MM-DD> --emit all -o $W/daily.txt && \
uv run python scripts/gen_technical_chart.py <TICKER> --name "<이름>" --interval 1wk \
  --close-on <YYYY-MM-DD> --emit all -o $W/weekly.txt
# 삽입도 스크립트로 (SVG를 heredoc으로 다시 타이핑하지 말 것)
```

대화로 받아도 되는 건 `--emit dates`·`--emit facts`처럼 짧은 것뿐이다. 서술(3. 관측된 특이 구간)과 파라미터 변경 사유(4. 방법론 · 한계)는 사람이 채운다.

### 5-2. `11_final_report.md`

**01~10이 다 채워진 뒤 가장 마지막.** 새 숫자·새 판단을 만들지 않고 인용·요약만 한다. 거시 환경에는 이 회사와 실제로 연결되는 macro 문서만 고르고(할인율 근거로는 대개 `rates/treasury_10y.md`), 인용할 차트가 낡았으면 먼저 갱신한다.

### 5-3. 마무리 체크리스트

여기서만 폴더 전체를 훑는다. **확인 명령은 한 콜에 묶어 실행한다.**

```bash
D=docs/sectors/<sector>/<company>
grep -rn "> ⚠️" $D/ ; echo "@@@ 작성일 @@@"; grep -rn "작성일" $D/*.md
echo "@@@ 종가 정합 @@@"; grep -rn "<종가값>" --include='*.md' docs/sectors/<sector>/
uv run mkdocs build 2>&1 | grep -i "unrecognized relative link" | head
```

- **`> ⚠️` 지침 블록이 하나도 남지 않았는지** — 위 `grep`이 비어야 한다. `!!! …`·`??? …`는 독자용이니 실제 내용으로 채워 남긴다(규칙 마스터: `authoring-guide.md` "표기법이 곧 발행 여부를 뜻한다")
- 1-1의 `carryover.md`에 추려둔 항목이 새 문서에 실제로 반영됐는지
- `04_metrics.md` 수치를 인용한 문서(`05`·`06`·`07`·`11`, 종가가 겹치면 `09`·`10`)가 서로 일치하는지 — grep으로 실제 검색할 것
- `*작성일*` — 오늘 날짜는 `# currentDate` → `date +%Y-%m-%d` → 확인 불가 시 사용자에게 확인
- 신규 섹터라면 `docs/sectors/.pages` 등록 재확인. 이번에 `00_glossary.md`를 만들었다면 **그 섹터 폴더의 `.pages`**도 있는지 본다(없으면 회사 폴더 사이에 섞여 나온다)
- 확인 못 한 값이 확정치처럼 남아 있지 않은지 — (E)·출처 각주·"확인 필요"가 남아 있어야 한다

끝나면 `.work/<company>/`를 지워도 된다(gitignore 대상이라 저장소에는 남지 않는다).

보고할 때는 확인한 것과 확인하지 못한 것을 구분해서 말한다.

## 하지 않는 것

- 회사 문서에서 새 용어를 정의하는 것 — `glossary.md`·`concepts/`(또는 섹터 전용이면 `docs/sectors/<sector>/00_glossary.md`)를 먼저 갱신
- "사라/팔아라" 식 단정적 투자 권유 — 근거와 불확실성을 함께 제시
- 커밋·푸시 — 사용자가 명시적으로 요청할 때만
- 작업을 여러 세션으로 쪼개고 사용자에게 새 세션에서 이어가라고 안내하는 것 — 위 "한 세션에서 끝낸다"
- 재무 수치 조사를 서브에이전트에 넘기는 것 — 2-1의 스크립트가 대체한다
- 10-K HTML을 텍스트로 바꿔 `grep`으로 캐는 것 — 스크립트가 못 주는 항목에 한해서만
- 독립적인 도구 호출을 한 턴에 하나씩 내는 것 — 위 "턴을 낭비하지 않는 법"

## 참고

폴더 구조·파일별 역할의 마스터는 `authoring-guide.md`, 검증·리뷰 기준은 `AGENTS.md`다 — 이 스킬은 그 규칙을 작성 흐름 순서로 적용할 뿐 새 기준을 만들지 않는다. 차트 스크립트는 `chart-generation-guide.md`, 재무 수치 스크립트는 `scripts/fetch_sec_facts.py`의 docstring이 마스터. 저장소 주인용 사용법은 같은 폴더의 `USAGE.md`.
