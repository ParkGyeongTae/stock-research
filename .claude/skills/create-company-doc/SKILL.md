# 회사 문서 신규 작성

## 언제 쓰나

- 대상: 이 저장소에 아직 없는 회사를 새로 커버리지에 추가하는 작업
- 트리거 예시: "<회사명> 문서 새로 만들어줘", "템플릿으로 <회사명> 추가해줘", "<회사명> 커버리지 시작하자"
- **대상 아님**:
  - 이미 존재하는 회사 폴더를 고치는 작업 → `improve-company-doc` 대상
  - `docs/index.md`·`AGENTS.md` 자체 개선 → `review-master-docs` 대상

## 왜 필요한가

템플릿을 복사하는 것 자체는 `cp -r` 한 줄이라 실수할 일이 적지만, 그다음 "내용을 채우는" 단계에서 사고가 난다 — 확인 안 된 수치를 확정치처럼 적거나, 무배당 기업에 DDM을 기계적으로 적용하거나, Bull Case만 채우고 Bear Case를 부실하게 남기는 식이다. 이 스킬은 폴더 생성부터 콘텐츠 채우기, 마무리 체크리스트까지 한 번의 신규 작성 흐름 안에서 `AGENTS.md`의 시니어 애널리스트 기준을 처음부터 적용하게 한다.

## 절차

1. **섹터·폴더명 확정**
   - 이미 있는 섹터인지 `docs/sectors/`를 확인한다. 없으면 신규 섹터 — 사용자에게 섹터명을 확인하거나 사업 성격상 가장 맞는 섹터를 제안한다.
   - 섹터 폴더명: 풀어 쓴 소문자 스네이크케이스 (예: `electronic_design_automation`)
   - 회사 폴더명: 회사명 소문자 스네이크케이스 (예: `synopsys`)
   - 복합기업이면 "관심을 갖게 된 사업" 기준으로 섹터를 정한다 — 매출 비중이 가장 큰 사업이 아니라, 이 저장소에서 그 회사를 보는 이유가 되는 사업 기준.

2. **템플릿 복사**
   명령은 `authoring-guide.md` "➕ 새 회사 / 새 섹터 추가 방법"의 1번 그대로 따른다.
   신규 섹터라면 `docs/sectors/.pages`의 `nav:`에 폴더명을 추가한다(등록 안 해도 빌드는 성공하지만 내비게이션에서 조용히 빠진다 — 경고 없음). 완전히 새로운 섹터라면 `create-sector-doc` 스킬로 `00_overview.md`(산업 개요)도 함께 만든다 — 빠뜨려도 에러는 안 나지만, 이 회사 `01_overview.md` 3. 산업 / 시장 내 위치가 걸려고 하는 링크 대상이 없어진다.

3. **원자료부터 채운다 — `04_metrics.md`가 먼저**
   - 이 파일이 이후 모든 문서가 인용하는 단일 출처다. 연간 표(최근 3개년+올해)·분기 표(최근 6개 분기)·사업 고유 지표(있다면)·판단 메모 순으로 채운다.
   - 사업 고유 지표(C절)는 섹터 단위로 정한다 — 같은 섹터에 이미 커버리지 회사가 있으면 그 회사의 지표를 따르고, 첫 회사면 여기서 정한다. 최대 5개, `glossary.md` 5. 사업 모델 · 성장 지표에 없는 지표면 거기부터 갱신한다. 단순한 사업이면 C절을 통째로 삭제하고 사유를 각주로 남긴다.
   - 수치는 기억으로 단정하지 않는다. WebFetch/WebSearch로 확인하고, 출처 우선순위는 1차 공시(10-K/10-Q/8-K/DEF 14A) > IR·실적발표 > 집계 사이트(stockanalysis, GuruFocus 등) > 언론 순. 집계 사이트끼리 값이 갈리면 하나를 단정하지 말고 범위로 남겨 민감도 분석에서 다룬다. 확인 못 한 값은 (E) + 출처 각주.
   - 표 기간 안에 주식분할이 있었으면 전 구간(주가·EPS·BPS·DPS·주식수)을 조정 후 기준으로 맞춘다.

4. **나머지 파일을 숫자→해석 순서로 채운다**
   - `01_overview.md`(필수) → `02_history.md`·`03_ceo.md`(선택) → `05_financials.md`(서술형 해석, 표는 새로 만들지 않고 `04_metrics.md` 인용) → `06_valuation.md` → `07_investment.md` → `08_news.md`
   - `06_valuation.md`: 템플릿의 "적용 여부 판단 기준"을 실제로 따져서 방법론을 고른다 — 무배당 기업에 DDM을 쓰지 않고, 고성장 기업에 1단계 DCF를 억지로 쓰지 않는다. 4개 방법론을 기계적으로 다 채우지 말고, 해당 없는 방법론은 왜 뺐는지 명시한다. 할인율과 현금흐름의 짝(WACC↔FCFF, Ke↔FCFE)을 섞지 않는다.
   - `07_investment.md`: Bull Case뿐 아니라 **Bear Case에 트리거(관찰 가능한 하방 사건) / 하방 밸류에이션 결과(대략 어떤 배수·주가) / 확인·기각 신호(kill signal)** 세 가지가 모두 있어야 한다. 이 저장소는 낙관 편향이 기본값이라 Bear Case를 더 엄격히 채운다. 밸류에이션 숫자(사실)와 투자 판단(의견)을 같은 문장에 섞지 않는다.
   - GAAP/Non-GAAP, 부채총계 vs 이자부 차입금 같은 정의가 불확실하면 "확인 필요"로 남기고 맞다고 가정해 계산에 넣지 않는다.

5. **불필요한 파일 정리**
   - 처음엔 `01_overview.md`만 있어도 된다. 나머지는 분석이 깊어지는 만큼만 남기고, 안 쓸 파일은 삭제한다(`01_overview.md`는 유지 권장).

6. **기술적 분석 차트(09·10)를 쓴다면 손으로 만들지 않는다**
   명령은 `chart-generation-guide.md` "기술적 분석 차트 생성" 절 그대로 따른다(`scripts/gen_technical_chart.py`, `--interval`만 다름).
   짧은 상장 기간 등으로 5년 주봉이 무의미하면 `10_technical_weekly.md` 자체를 생략해도 된다.

7. **최종 보고서(`11_final_report.md`)는 01~10이 다 채워진 뒤 가장 마지막에 쓴다**
   규칙은 `authoring-guide.md` "`11_final_report.md` 작성 규칙" 그대로 따른다 — 이 문서에서 새 숫자·새 판단을 만들지 않고 `01~10`을 인용·요약만 한다.
   6. 거시 환경 (Macro Backdrop)에 넣을 `docs/meta/macro/` 문서는 이 회사와 실제로 연결되는 것만 고른다(예: 원자재 노출이 크면 `energy`/`metals`, 밸류에이션 할인율 근거로는 대부분 `rates/treasury_10y.md`) — 카테고리 전체를 나열하지 않는다. 인용할 macro 문서의 차트가 오래됐으면 먼저 갱신한다.
   9. 시나리오 요약은 `06_valuation.md`의 가격과 `07_investment.md`의 리스크를 표로 재배치할 뿐 새로 계산하지 않는다.

8. **마무리 체크리스트** (`AGENTS.md` "작업을 마치기 전에" 그대로 적용)
   - **템플릿에서 온 `> ⚠️` 작성자 지침 블록이 하나도 남지 않았는지** — 규칙은 `authoring-guide.md` "표기법이 곧 발행 여부를 뜻한다"가 마스터다(템플릿 안에는 더 이상 이 설명이 없다). `> ⚠️`는 전부 지우고, `!!! …`·`??? …`는 독자용이니 실제 내용으로 채워 남긴다. `grep -rn "> ⚠️" docs/sectors/<sector>/<company>/`로 확인한다
   - `*작성일*` 표기 — 오늘 날짜는 세션 컨텍스트 `# currentDate` → `date +%Y-%m-%d` → 확인 불가 시 사용자에게 확인
   - 신규 섹터라면 `docs/sectors/.pages` 등록을 실제로 했는지 재확인
   - `uv run mkdocs build`로 깨진 링크(`unrecognized relative link`) 없는지 확인
   - 확인 못 한 값이 확정치처럼 남아 있지 않은지 — (E) 표기와 출처 각주, "확인 필요" 표기가 남아 있어야 한다
   - `11_final_report.md`가 01~10의 최신 값과 어긋나지 않는지 — 특히 `04_metrics.md`·`06_valuation.md`·`07_investment.md`를 마지막에 다시 손봤다면 이 문서도 함께 확인

## 하지 않는 것

- 회사 문서 안에서 새 용어를 정의하는 것 — 없는 개념이 필요하면 `glossary.md`·`concepts/`를 먼저 갱신
- "사라/팔아라" 식 단정적 투자 권유 — 근거와 불확실성을 함께 제시
- 커밋·푸시 — `AGENTS.md` 커밋 정책대로 사용자가 명시적으로 요청할 때만

## 참고

- 폴더 구조·파일별 역할의 마스터는 `authoring-guide.md`, 콘텐츠 검증·리뷰 기준은 `AGENTS.md`다 — 이 스킬은 신규 작성이라는 한 흐름 안에서 그 규칙들을 순서대로 적용할 뿐, 새 기준을 만들지 않는다.
