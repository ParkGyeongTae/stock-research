# 회사 문서 작성 (신규 · 재생성 공통)

## 언제 쓰나

- 신규: "<회사명> 문서 만들어줘", "<회사명> 커버리지 시작하자"
- 재생성: "<회사명> 문서 개선해줘 / 업데이트해줘 / 최신화해줘 / 템플릿 기준으로 다시 봐줘"
- **대상 아님**: 섹터 개요 → `create-sector-doc` · 거시지표 → `create-macro-doc` · `AGENTS.md`·`authoring-guide.md` 자체 검토 → `review-master-docs`

## 왜 이렇게 하나

기존 폴더를 부분 수정하면 눈에 띄는 절만 고치고 넘어가게 되고, 템플릿이 바뀐 뒤에도 옛 절 구성·옛 항목 수가 그대로 남는다. 그래서 **개선 요청도 재생성으로 처리한다** — 폴더를 지우고 현재 템플릿으로 새로 만들면 구조가 항상 최신이고, 모든 수치를 다시 검증하게 된다. 지운 내용은 git 히스토리에 남으므로 영구 손실은 아니다.

## 이 작업은 세 단계로 끊어서 한다

회사 폴더 하나를 한 대화에서 끝까지 만들면 **뒤로 갈수록 한 턴이 급격히 비싸진다.** 대화가 길어질수록 매 턴 그 전체가 입력에 다시 실리기 때문이다. 실측(Expand Energy, 한 대화 276콜):

| 구간 | 그 구간이 쓴 몫 |
|---|---|
| 앞 1/4 | 12% |
| 뒤 1/4 (`09`·`10`·`11`·검증) | **47%** |

마지막 구간에서 하는 일은 `sed` 한 줄 고치기 같은 값싼 작업인데도 전체의 절반을 썼다. **문서를 짧게 쓰는 것으로는 해결되지 않는다** — 모델이 써낸 분량은 전체 비용의 1% 미만이다. 대화를 끊어야 준다.

그래서 아래 세 단계로 나누고, **각 단계가 끝나면 사용자에게 `/clear`를 안내한 뒤 멈춘다.** 단계 사이의 인수인계는 대화가 아니라 **디스크에 쓰인 문서 자체**로 한다.

| 단계 | 만드는 것 | 다음 단계가 읽어갈 것 |
|---|---|---|
| **1** | 폴더 준비 + `04_metrics.md` | `04_metrics.md` (모든 수치의 단일 출처) |
| **2** | `01`·`02`·`03`·`05`·`06`·`07`·`08` | 위 + `06_valuation.md` 결론 |
| **3** | `09`·`10`·`11` + 마무리 체크리스트 | — |

### 시작 게이트 — 여기서 멈추지 않으면 분할이 무의미하다

**실측된 실패 사례**: EQT 때 사용자가 1단계 종료 안내를 받고도 `/clear` 없이 같은 대화에서 "2단계 진행해줘"라고 이어갔다. 1단계 컨텍스트를 그대로 얹은 채 2단계가 돌았고, 분할이 절감하는 유일한 경로("대화를 버리는 것")가 사라졌다. **결과적으로 01~08을 만드는 데 분할 전(5,063k)보다 37% 많은 6,936k를 썼다.** 아래 게이트는 그 재발을 막는 장치다.

시작할 때 **순서대로** 확인한다.

**(1) 이 대화가 새 대화인가.** 현재 대화에 이 회사의 앞 단계 작업 흔적(같은 회사 폴더에 대한 `rm -rf`·템플릿 복사·`04_metrics.md` 작성 등)이 이미 있으면 **다음 단계를 진행하지 말고 멈춘다.** 사용자에게 이렇게 말한다:

> 이 대화에는 이미 <회사명> N단계 작업이 들어 있습니다. 이어서 진행하면 그 컨텍스트가 계속 실려 분할 효과가 사라집니다(실측: 같은 범위에 +37%). `/clear` 후 "<회사명> N+1단계 진행해줘"라고 해주세요.

사용자가 그래도 이어서 하라고 하면 그 판단을 따르되, **추가 비용을 감수하는 선택임을 한 줄로 알리고** 진행한다.

**(2) 몇 단계인가.** 템플릿 파일에는 `> ⚠️` 지침 블록이 반드시 남아 있고(파일당 2개 이상), 다 채운 파일에는 하나도 없다. 그러니 아직 안 끝난 파일이 곧 지금 할 일이다:

```bash
grep -l '^> ⚠️' docs/sectors/<sector>/<company>/*.md 2>/dev/null | sed 's#.*/##'
```

- 폴더가 없거나 전부 걸린다 → **1단계**
- `04`만 빠지고 나머지가 걸린다 → **2단계**
- `09`·`10`·`11`만 걸린다 → **3단계**
- 아무것도 안 걸린다 → 이미 완료. 사용자에게 확인하고, 재생성이면 1단계부터.

판정 결과를 사용자에게 한 줄로 알리고 그 단계만 수행한다. **앞 단계 문서를 다시 읽어 검토하지 않는다** — 그러라고 디스크에 쓴 것이다. 필요한 값만 `grep`/`sed -n`으로 뽑아 쓴다.

## 턴을 낭비하지 않는 법

단계 분할 다음으로 큰 절감은 **도구 호출 횟수**에서 나온다. 실측 세션들은 회사 하나에 300~380콜을 썼고, 그 대부분이 SEC 문서를 텍스트로 바꿔 `grep`으로 훑는 반복이었다(한 세션에서 같은 `10k.txt`에 86회).

- **1차 공시 재무 수치는 스크립트로 한 번에 가져온다.** 아래 1-3 참고. 10-K HTML을 내려받아 `grep`으로 캐는 방식은 쓰지 않는다.
- **읽기는 한 콜에 묶는다.** 파일 서너 개를 볼 거면 `sed -n`/`cat`을 `echo` 구분자와 함께 한 번에 실행한다.
- **쓰기는 수치 검증이 끝난 뒤 한 번에 한다.** 가장 비쌌던 건 문서를 먼저 쓰고 나중에 `sed -i`로 깁던 수정 라운드였다 — 컨텍스트가 커진 시점에 한 줄 고치는 게 제일 비싸다. 값이 확정되지 않았으면 쓰지 말고, 확정됐으면 heredoc 한 번으로 끝낸다.
- **한 콜에 독립적인 일을 몰아넣는다.** 서로 의존하지 않는 명령은 `&&`/`;`로 이어 붙인다.
- **스크립트 산출물을 대화로 통과시키지 않는다.** `gen_technical_chart.py`의 SVG는 수만 자다. 반드시 파일로 리다이렉트하고 스크립트로 삽입한다 (3단계 참고).

### 서브에이전트에 조사를 통째로 넘기지 않는다

한때 이 스킬은 "웹 조사를 서브에이전트에 위임하면 원문이 본 세션에 안 쌓인다"고 지시했다. **실측 결과 틀렸다.** EQT에서 서브에이전트 2개가 252콜을 돌며 본 세션(16.5M)보다 많은 22.1M의 컨텍스트를 쌓았다. 정성 조사 에이전트 하나가 154턴 동안 Bash를 89번 부르며 예전에 본 세션이 하던 `10k.txt` 파헤치기를 그대로 반복했다. 조사 루프를 옮기면 그 루프의 컨텍스트도 같이 따라가고, 게다가 서브에이전트는 부모와 프롬프트 캐시를 공유하지 못해 시스템 프롬프트·`AGENTS.md`·툴 스키마를 새로 적재한다. **긴 대화 하나가 콜드 스타트 루프 둘보다 싸다.**

그래서:

- **재무 수치 조사는 서브에이전트를 쓰지 않는다.** 1-3의 스크립트가 그 일을 한 콜로 대체한다.
- **정성 정보(연혁·경영진·경쟁·리스크 요인)는 기본적으로 본 세션에서 직접 조사한다.** WebSearch·WebFetch 몇 번이면 되는 일에 에이전트를 띄우지 않는다.
- 예외적으로 위임할 때는 **최대 1개**만 띄우고, 프롬프트에 반드시 넣는다:
  - "도구 호출 **25회 이내**로 끝낼 것. 못 채운 항목은 '확인 실패'로 남기고 더 파지 말 것"
  - "결과 전문은 `<scratchpad>/facts.md`에 쓰고, **응답으로는 40줄 이내 요약과 그 파일 경로만** 반환할 것"
  - 출처 우선순위(1차 공시 > IR > 집계 사이트 > 언론), 모든 수치에 출처 URL, 집계 사이트가 갈리면 범위로, 정의가 갈리는 항목은 "확인 필요"로, 서술·해석·투자 판단 금지

## 1단계 — 폴더 준비 + `04_metrics.md`

### 1-1. 재생성이면, 지우기 전에 옮길 것부터 추린다

기존 폴더가 있으면 **먼저 읽고**, 웹에서 다시 못 구하는 항목만 메모해 둔다. 그 외에는 전부 새로 조사한다. 읽기는 한 콜에 묶는다.

- `08_news.md` 로그 (발생 시점과 그때의 판단 기록)
- `04_metrics.md`의 `!!! warning` — 이 회사 고유의 오독 위험(분할 소급조정 이력, 일회성 손익, 짧은 상장 이력)
- `04_metrics.md` C절의 사업 고유 지표 목록과 정의 — **섹터 단위로 합의된 값**이라 임의로 바꾸면 같은 섹터 회사와 비교가 깨진다
- `06_valuation.md`의 방법론 채택·제외 사유와 가중치 근거

추린 내용은 **폴더를 지우기 전에 scratchpad 파일로 저장한다.** 대화에만 들고 있으면 단계를 넘어가면서 사라진다.

### 1-2. 폴더 삭제 후 템플릿 복사

```bash
rm -rf docs/sectors/<sector>/<company>
cp -r docs/meta/.template/company docs/sectors/<sector>/<company>
```

신규 섹터라면 폴더명은 풀어 쓴 소문자 스네이크케이스(`electronic_design_automation`), 회사 폴더명은 회사명 스네이크케이스(`synopsys`). 복합기업은 매출 비중이 아니라 **"이 저장소에서 그 회사를 보는 이유"가 되는 사업** 기준으로 섹터를 정한다. 섹터 폴더가 새로 생기면 `docs/sectors/.pages`에 등록하고(안 하면 경고 없이 내비게이션에서 빠진다), 산업 개요는 `create-sector-doc`으로 함께 만든다.

### 1-3. GAAP 수치를 스크립트로 먼저 확보한다

`04_metrics.md` A절·B절의 뼈대는 **SEC가 회사로부터 XBRL로 받아둔 값**으로 채운다. 10-K를 텍스트로 바꿔 훑지 않는다.

```bash
S=<scratchpad>
uv run python scripts/fetch_sec_facts.py <TICKER> --emit all -o $S/facts.md
sed -n '1,80p' $S/facts.md    # 표는 80줄 안쪽이므로 한 번에 읽어도 된다
```

- 셀별 원공시(form·제출일·accession)가 필요하면 `--emit sources`. 소급 수정된 값에는 `*`, 파생값(Q4 = FY − Q1·Q2·Q3, 이자부 차입금 합계)에는 `ᵈ`가 붙는다 — **파생값을 인용할 땐 문서에도 파생임을 밝힌다.**
- 이 스크립트는 **지배주주 귀속 vs 연결(NCI 포함)**, **부채총계 vs 이자부 차입금**을 각각 별도 행으로 준다. 이 저장소가 반복해서 틀리던 지점이므로 행을 합치지 말 것.
- 여기서 나오는 값은 **전부 GAAP이다.** Adjusted EBITDA·Adjusted EPS 같은 Non-GAAP은 XBRL에 없으므로 8-K Ex-99 실적발표에서 따로 확인하고 라벨을 붙인다.
- `—`는 "값이 없음"이 아니라 "그 태그로 태깅하지 않음"이다. 결론을 좌우하는 항목이 `—`로 비면 그때만 공시 원문을 확인한다.
- 스크립트가 못 주는 것: 종가·시가총액·베타·컨센서스·가이던스·사업 고유 지표(생산량·매장량 등). 이건 본 세션에서 조사한다.

### 1-4. `04_metrics.md` — 이후 모든 문서가 인용하는 단일 출처

A(연간)·B(분기)·C(사업 고유)·D(판단 메모) 순으로 채운다.

- **수치는 기억으로 단정하지 않는다.** 확인 못 한 값은 (E) + 출처 각주.
- 표 기간 안에 주식분할이 있었으면 전 구간(주가·EPS·BPS·DPS·주식수)을 조정 후 기준으로 맞춘다.
- C절은 섹터 단위로 정한다 — 같은 섹터에 회사가 이미 있으면 그 지표를 따르고, 첫 회사면 여기서 정한다. 최대 5개. `glossary.md`에 없는 지표면 거기부터 갱신한다. 단순한 사업이면 C절을 통째로 삭제하고 사유를 A절 각주에 남긴다.
- 정의가 불확실하면(GAAP/Non-GAAP, 부채총계 vs 이자부 차입금) "확인 필요"로 남기고 맞다고 가정해 계산에 넣지 않는다.

### 1-5. 단계 종료

`grep -c '^> ⚠️' …/04_metrics.md`가 0인지 확인하고, 1-1에서 추린 메모가 반영됐는지 본다. 그다음 **작업을 멈추고** 사용자에게 알린다:

> 1단계(`04_metrics.md`) 완료했습니다. **`/clear` 후** "<회사명> 2단계 진행해줘"라고 하시면 이어서 진행합니다. `/clear` 없이 이어가면 이 대화가 계속 실려 비용이 크게 늘어납니다.

## 2단계 — `01`·`02`·`03`·`05`·`06`·`07`·`08`

**새 대화에서 시작한다** — 위 "시작 게이트"를 먼저 통과할 것.

`04_metrics.md`에서 필요한 값만 뽑아 쓴다(파일 전체를 통째로 읽지 말고 해당 절만). 순서는 `01` → `02` → `03` → `05` → `06` → `07` → `08`. **전부 필수라 하나도 빼지 않는다.**

- 정성 정보(연혁·경영진·경쟁 환경·리스크 요인)는 본 세션에서 직접 조사한다. 출처는 10-K Item 1·1A와 DEF 14A가 우선.
- `06_valuation.md`: 템플릿의 "적용 여부 판단 기준"을 실제로 따진다 — 무배당 기업에 DDM을 쓰지 않고, 고성장 기업에 1단계 DCF를 억지로 쓰지 않는다. 해당 없는 방법론은 왜 뺐는지 명시한다. **할인율과 현금흐름의 짝(Ke↔FCFE, WACC↔FCFF)을 섞지 않는다.** 1단계 DCF 결론이 다른 방법론과 크게 어긋나면 각주로 넘기지 말고 가중치를 낮추거나 뺀다.
- `07_investment.md`: Bear Case에 **트리거 / 하방 밸류에이션 / 확인·기각 신호** 셋이 모두 있어야 한다. 이 저장소는 낙관 편향이 기본값이라 여기를 더 엄격히 채운다.
- `08_news.md`: 1단계에서 옮겨둔 기존 로그를 여기서 되살린다.

## 3단계 — `09`·`10`·`11` + 마무리

**새 대화에서 시작한다** — 위 "시작 게이트"를 먼저 통과할 것. 실측상 이 구간이 가장 비싸므로(전체의 47%) 컨텍스트를 깨끗이 두고 들어가는 이득이 제일 크다.

### 3-1. 차트 (`09`·`10`)

SVG·레벨 표·방법론 수치를 손으로 만들지 않는다 — 커맨드는 `chart-generation-guide.md` "기술적 분석 차트 생성"이 마스터.

**산출물을 대화로 통과시키지 않는다.** SVG는 파일당 수만 자라 한 번 컨텍스트에 들어오면 남은 턴 내내 곱해진다. 반드시 이렇게 한다:

```bash
# 1) 산출물을 scratchpad 파일로 — `-o`를 쓴다.
#    `> file 2>&1`로 받으면 스크립트의 경고·완료 메시지가 stderr로 파일에 섞여 문서를 오염시킨다.
S=<scratchpad>
uv run python scripts/gen_technical_chart.py <TICKER> --name "<이름>" \
  --close-on <YYYY-MM-DD> --emit all -o $S/daily.txt
uv run python scripts/gen_technical_chart.py <TICKER> --name "<이름>" --interval 1wk \
  --close-on <YYYY-MM-DD> --emit all -o $S/weekly.txt
# 2) 삽입도 스크립트로 (SVG를 heredoc으로 다시 타이핑하지 말 것)
```

대화로 받아도 되는 건 `--emit dates`·`--emit facts`처럼 짧은 것뿐이다. 서술(3. 관측된 특이 구간)과 파라미터 변경 사유(4. 방법론 · 한계)는 사람이 채운다.

### 3-2. `11_final_report.md`

**01~10이 다 채워진 뒤 가장 마지막.** 새 숫자·새 판단을 만들지 않고 인용·요약만 한다. 거시 환경에는 이 회사와 실제로 연결되는 macro 문서만 고르고(할인율 근거로는 대개 `rates/treasury_10y.md`), 인용할 차트가 낡았으면 먼저 갱신한다.

### 3-3. 마무리 체크리스트

여기서만 폴더 전체를 훑는다. 확인 명령은 한 콜에 묶어 실행한다.

- **`> ⚠️` 지침 블록이 하나도 남지 않았는지** — `grep -rn "> ⚠️" docs/sectors/<sector>/<company>/`가 비어야 한다. `!!! …`·`??? …`는 독자용이니 실제 내용으로 채워 남긴다(규칙 마스터: `authoring-guide.md` "표기법이 곧 발행 여부를 뜻한다")
- 1단계에서 추려둔 항목이 새 문서에 실제로 반영됐는지
- `04_metrics.md` 수치를 인용한 문서(`05`·`06`·`07`·`11`, 종가가 겹치면 `09`·`10`)가 서로 일치하는지 — grep으로 실제 검색할 것
- `*작성일*` — 오늘 날짜는 `# currentDate` → `date +%Y-%m-%d` → 확인 불가 시 사용자에게 확인
- 신규 섹터라면 `docs/sectors/.pages` 등록 재확인
- `uv run mkdocs build`로 `unrecognized relative link` 없는지 확인
- 확인 못 한 값이 확정치처럼 남아 있지 않은지 — (E)·출처 각주·"확인 필요"가 남아 있어야 한다

보고할 때는 확인한 것과 확인하지 못한 것을 구분해서 말한다.

## 하지 않는 것
