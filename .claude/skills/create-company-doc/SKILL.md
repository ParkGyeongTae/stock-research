# 회사 문서 작성 (신규 · 재생성 공통)

## 언제 쓰나

- **신규**: "<회사명> 문서 만들어줘", "<회사명> 커버리지 시작하자"
- **재생성**: "<회사명> 문서 개선해줘 / 업데이트해줘 / 최신화해줘 / 템플릿 기준으로 다시 봐줘"
- **대상 아님**: 거시지표 → `create-macro-doc`

개선 요청도 **재생성으로 처리한다** — 부분 수정하면 눈에 띄는 절만 고치고 템플릿이 바뀐 뒤에도 옛 구조가 남는다. 지운 내용은 git 히스토리에 남는다.

## 작업 방식

회사 폴더 하나는 **한 대화에서 끝까지** 만든다. 사용자에게 새 세션에서 이어가라고 안내하지 않는다. 아래를 응답에 복사해 두고 단계마다 표시한다.

```
- [ ] 1. 폴더 준비 (carryover 추출 → 삭제 → 템플릿 복사)
- [ ] 2. 04_metrics.md — 이후 모든 문서가 인용하는 단일 출처
- [ ] 3. 01·02·03·05·08 — 정성 조사
- [ ] 4. 06·07 — 밸류에이션·투자 판단
- [ ] 5. 09·10·11 + 마무리 검증
```

**서로 기다릴 필요 없는 도구 호출은 한 턴에 몰아서 낸다** — 검색 4~5개, 파일 읽기 여러 개, 문서 5개 쓰기, 검증 명령이 전부 해당한다. 파일을 통째로 `cat` 하지 말고 `sed -n`으로 필요한 절만 뽑는다. 근거와 세부 규칙은 [reference/context-budget.md](reference/context-budget.md).

**중단됐다 재개할 때**는 처음부터 다시 하지 않는다. 템플릿에는 `> ⚠️` 지침 블록이 남아 있고 다 채운 파일에는 하나도 없다:

```bash
grep -l '^> ⚠️' docs/sectors/<sector>/<company>/*.md 2>/dev/null | sed 's#.*/##' | tr '\n' ' '
```

걸리는 파일이 곧 남은 일이다. 이미 채운 문서는 다시 읽어 검토하지 않는다.

## 1. 폴더 준비

**재생성이면 지우기 전에 옮길 것부터 추린다.** 웹에서 다시 못 구하는 것만 `.work/<company>/carryover.md`에 저장하고(읽기는 한 콜로 묶는다), 그 외는 전부 새로 조사한다.

- `08_news.md` 로그 — 발생 시점과 그때의 판단
- `04_metrics.md`의 `!!! warning` — 이 회사 고유의 오독 위험(분할 소급조정, 일회성 손익, 짧은 상장 이력)
- `04_metrics.md` C절 지표 목록과 정의 — 섹터 단위 합의값이라 임의로 바꾸면 동종사 비교가 깨진다
- `06_valuation.md`의 방법론 채택·제외 사유와 가중치 근거

```bash
mkdir -p .work/<company>
rm -rf docs/sectors/<sector>/<company>
cp -r docs/authoring/template/company docs/sectors/<sector>/<company>
```

사용자가 섹터를 지정하지 않았으면 `ls docs/sectors/`로 목록을 확인해 제안한 뒤 진행한다. 폴더명은 소문자 스네이크케이스(섹터 `electronic_design_automation`, 회사 `synopsys`). 복합기업은 매출 비중이 아니라 **"이 저장소에서 그 회사를 보는 이유"가 되는 사업**으로 섹터를 정한다. 섹터 폴더를 새로 만들면 `docs/sectors/.pages`에 등록한다(빠뜨리면 경고 없이 내비게이션에서 사라진다).

**섹터 폴더에 산업 분석·개요 문서를 두지 않는다** — 산업 분석은 각 회사 `01_overview.md`의 "산업 / 시장 내 위치"에서 그 회사 관점으로만 다룬다. 예외는 섹터 전용 용어를 모으는 `00_glossary.md`뿐이고, 여긴 정의만 담고 분석·전망은 담지 않는다.

## 2. `04_metrics.md`

### 2-1. GAAP 수치는 스크립트로 확보한다

A·B절의 뼈대는 SEC가 XBRL로 받아둔 값으로 채운다. 10-K를 텍스트로 바꿔 훑지 않는다.

```bash
uv run python scripts/fetch_sec_facts.py <TICKER> --emit all -o .work/<company>/facts_sec.md
sed -n '1,80p' .work/<company>/facts_sec.md    # 표는 80줄 안쪽이라 한 번에 읽어도 된다
```

- 셀별 원공시(form·제출일·accession)가 필요하면 `--emit sources`. 소급 수정값에 `*`, 파생값(Q4 = FY − Q1·Q2·Q3, 이자부 차입금 합계)에 `ᵈ`가 붙는다 — **파생값을 인용할 땐 문서에도 파생임을 밝힌다.**
- **지배주주 귀속 vs 연결(NCI 포함)**, **부채총계 vs 이자부 차입금**이 각각 별도 행으로 나온다. 이 저장소가 반복해서 틀리던 지점이므로 행을 합치지 않는다.
- 여기 나오는 값은 전부 GAAP이다. Adjusted EBITDA·Adjusted EPS 같은 Non-GAAP은 8-K Ex-99 실적발표에서 따로 확인하고 라벨을 붙인다.
- `—`는 "값이 없음"이 아니라 "그 태그로 태깅하지 않음"이다. 결론을 좌우하는 항목이 비면 그때만 공시 원문을 본다.
- 스크립트가 못 주는 것(종가·시가총액·베타·컨센서스·가이던스·사업 고유 지표)은 **3단계 정성 조사와 같은 턴에 묶어** 검색한다.

### 2-2. 표를 채운다

A(연간)·B(분기)·C(사업 고유)·D(판단 메모)를 **한 번의 heredoc으로** 쓴다.

- 확인 못 한 값은 (E) + 출처 각주. 기억으로 단정하지 않는다.
- 표 기간에 주식분할이 있으면 전 구간(주가·EPS·BPS·DPS·주식수)을 조정 후 기준으로 맞춘다.
- 정의가 불확실하면(GAAP/Non-GAAP, 부채총계 vs 이자부 차입금) "확인 필요"로 남기고 맞다고 가정해 계산에 넣지 않는다.

### 2-3. C절은 섹터 단위로 정한다

같은 섹터에 회사가 있으면 그 지표를 따르고 첫 회사면 여기서 정한다(최대 5개). 없는 지표면 용어 문서를 먼저 갱신하되 **두 개 이상 섹터가 쓰면 `docs/glossary.md`, 이 섹터 전용이면 `docs/sectors/<sector>/00_glossary.md`**에 넣는다(후자가 없으면 만들고 `.pages`도 함께 둔다). 단순한 사업이면 C절을 통째로 삭제하고 사유를 A절 각주에 남긴다.

동종사 지표를 뽑는 명령은 [reference/sector-consistency.md](reference/sector-consistency.md) — 4-1의 가정 대조와 한 턴에 같이 낸다.

## 3. 정성 조사 → `01`·`02`·`03`·`05`·`08`

`04_metrics.md`가 담은 재무 수치는 다시 조사하지 않는다. 여기서 모으는 건 그 표가 못 담는 것이다.

- **연혁**: 회사 방향을 바꾼 전환점(창업·상장·지배구조 변경·매출 구조를 바꾼 M&A·존폐 위기). 월까지 표기, 출처 필수
- **경영진**: CEO 커리어·경영 스타일·보상·지분·차등의결권. DEF 14A 우선
- **사업 구조**: 부문별 매출 비중과 그 기준 회계연도(10-K Item 1·7), 지역별 매출
- **경쟁·리스크**: 10-K Item 1A 중 이 회사 고유의 것만. 섹터 공통 리스크는 이 회사에 어떻게 작용하는지까지 써야 남기고, 산업 일반론에 그치면 뺀다
- **밸류에이션 입력값**: 컨센서스 EPS, 베타·WACC·자기자본비용, 최근 종가와 기준일. **집계 사이트끼리 갈리면 한쪽을 고르지 말고 범위로 기록한다**
- **최근 뉴스** 5건 이내와 각각의 출처

출처 우선순위는 1차 공시(10-K/10-Q/8-K/DEF 14A) > 회사 IR·실적발표 > 집계 사이트 > 언론. 검색은 한 턴에 4~5개씩 묶고, 원문이 길면 `.work/<company>/`에 내려 필요한 줄만 대화로 올린다.

조사가 끝나면 다섯 문서를 **한 콜의 heredoc 묶음으로** 쓴다.

- `05_financials.md`는 서술형 해석 전용 — 표를 새로 만들지 말고 `04`의 값을 인용만 한다. 각 절 3~5문장.
- `08_news.md`는 `carryover.md`의 기존 로그를 되살린다.
- `02`·`03`은 위에서 모은 것만 쓴다. 여기서 새로 검색하지 않고, 빠진 건 "확인 필요"로 남긴다.

## 4. `06`·`07` — 판단이 걸린 구간

앞뒤 단계에서 아낀 사고 예산을 여기 쓴다.

### 4-1. 가정 대조

같은 섹터에 회사가 있으면 목표 배수·할인율·가중치를 먼저 대조한다 — 근거 없이 갈리면 두 회사의 적정주가를 나란히 볼 수 없다. 명령과 판정 기준은 [reference/sector-consistency.md](reference/sector-consistency.md). 섹터 첫 회사면 건너뛴다.

`04_metrics.md`에서 필요한 절만 한 콜로 가져온다(위 대조 명령과 같은 턴에):

```bash
D=docs/sectors/<sector>/<company>
sed -n '/^### 2. 밸류에이션 지표/,/^### 3\./p' $D/04_metrics.md
sed -n '/^### 3. 재무 건전성 지표/,/^## B\./p' $D/04_metrics.md
sed -n '/^## D\. 판단 메모/,$p' $D/04_metrics.md
```

### 4-2. `06_valuation.md`

템플릿의 "적용 여부 판단 기준"을 실제로 따진다 — 무배당 기업에 DDM을 쓰지 않고, 고성장 기업에 1단계 DCF를 억지로 쓰지 않는다. 뺀 방법론은 왜 뺐는지 명시한다. **할인율과 현금흐름의 짝(Ke↔FCFE, WACC↔FCFF)을 섞지 않는다** — `04` A.4의 FCF는 CFO−CapEx라 FCFE 성격이고 Ke로 할인한다. 1단계 DCF 결론이 다른 방법론과 크게 어긋나면 각주로 넘기지 말고 **가중치를 낮추거나 뺀다.**

### 4-3. `07_investment.md`

Bear Case에 **트리거 / 하방 밸류에이션 / 확인·기각 신호** 셋이 모두 있어야 한다. 이 저장소는 낙관 편향이 기본값이라 여기를 더 엄격히 채운다. 종합 적정주가는 `06`에서 인용하고 여기서 새로 계산하지 않는다.

## 5. `09`·`10`·`11` + 마무리

### 5-1. 차트 (`09`·`10`)

SVG·레벨 표·방법론 수치를 손으로 만들지 않는다 — 커맨드 마스터는 `docs/authoring/chart-generation-guide.md` "기술적 분석 차트 생성". 일봉·주봉을 한 콜에 내고 산출물은 반드시 파일로 받는다:

```bash
W=.work/<company>
uv run python scripts/gen_technical_chart.py <TICKER> --name "<이름>" \
  --close-on <YYYY-MM-DD> --emit all -o $W/daily.txt && \
uv run python scripts/gen_technical_chart.py <TICKER> --name "<이름>" --interval 1wk \
  --close-on <YYYY-MM-DD> --emit all -o $W/weekly.txt
```

`-o`를 쓴다 — `> file 2>&1`로 받으면 스크립트의 경고·완료 메시지가 stderr로 섞여 문서를 오염시킨다. 삽입도 스크립트로 하고 SVG를 heredoc으로 다시 타이핑하지 않는다. 대화로 받아도 되는 건 `--emit dates`·`--emit facts`뿐이다. 서술(3. 관측된 특이 구간)과 파라미터 변경 사유(4. 방법론 · 한계)는 직접 채운다.

### 5-2. `11_final_report.md`

**01~10이 다 채워진 뒤 가장 마지막.** 새 숫자·새 판단을 만들지 않고 인용·요약만 한다. 거시 환경에는 이 회사와 실제로 연결되는 macro 문서만 고르고(할인율 근거는 대개 `rates/treasury_10y.md`), 인용할 차트가 낡았으면 먼저 갱신한다.

### 5-3. 마무리 검증

여기서만 폴더 전체를 훑는다. 확인 명령은 한 콜로 묶는다:

```bash
D=docs/sectors/<sector>/<company>
grep -rn "> ⚠️" $D/ ; echo "@@@ 작성일 @@@"; grep -rn "작성일" $D/*.md
echo "@@@ 종가 정합 @@@"; grep -rn "<종가값>" --include='*.md' docs/sectors/<sector>/
uv run mkdocs build 2>&1 | grep -i "unrecognized relative link" | head
```

- **`> ⚠️` 지침 블록이 하나도 남지 않았는지** — 위 `grep`이 비어야 한다. `!!! …`·`??? …`는 독자용이니 실제 내용으로 채워 남긴다(마스터: `docs/authoring/authoring-guide.md`의 **표기법이 곧 "발행 여부"를 뜻한다** 항목)
- `carryover.md`에 추려둔 항목이 새 문서에 실제로 반영됐는지
- `04_metrics.md`를 인용한 문서(`05`·`06`·`07`·`11`, 종가가 겹치면 `09`·`10`)가 서로 일치하는지 — grep으로 실제 검색할 것
- `*작성일*` — 오늘 날짜는 `# currentDate` → `date +%Y-%m-%d` → 확인 불가 시 사용자에게 확인
- 신규 섹터면 `docs/sectors/.pages`, 이번에 `00_glossary.md`를 만들었으면 그 섹터 폴더의 `.pages`
- 확인 못 한 값이 확정치처럼 남아 있지 않은지 — (E)·출처 각주·"확인 필요"가 남아 있어야 한다

`.work/<company>/`는 지워도 된다(gitignore 대상이라 저장소에 남지 않는다). 보고할 때는 확인한 것과 확인하지 못한 것을 구분해서 말한다.

## 하지 않는 것

- 회사 문서에서 새 용어를 정의하는 것 — `docs/glossary.md`·`docs/concepts/`(섹터 전용이면 `00_glossary.md`)를 먼저 갱신
- "사라/팔아라" 식 단정적 투자 권유 — 근거와 불확실성을 함께 제시
- 커밋·푸시 — 사용자가 명시적으로 요청할 때만
- 조사를 서브에이전트에 넘기는 것 — 조사 루프의 컨텍스트가 같이 따라가고 프롬프트 캐시도 공유되지 않아 더 비싸다([reference/context-budget.md](reference/context-budget.md))
- 10-K HTML을 텍스트로 바꿔 `grep`으로 캐는 것 — 스크립트가 못 주는 항목에 한해서만

## 참고

폴더 구조·파일별 역할의 마스터는 `docs/authoring/authoring-guide.md`, 검증·리뷰 기준은 `AGENTS.md`다 — 이 스킬은 그 규칙을 작성 흐름 순서로 적용할 뿐 새 기준을 만들지 않는다. 차트 스크립트는 `docs/authoring/chart-generation-guide.md`, 재무 수치 스크립트는 `scripts/fetch_sec_facts.py`의 docstring이 마스터.
