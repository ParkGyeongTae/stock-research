# `create-company-doc` 사용법 (저장소 주인용)

같은 폴더의 [`SKILL.md`](./SKILL.md)는 **에이전트가 읽는 절차서**입니다. 이 문서는 그중 **내가 터미널에서 무엇을 치고 대화창에 뭐라고 말하는지**만 뽑은 것입니다. 규칙이 어긋나면 `SKILL.md`가 우선입니다.

---

## 한 장 요약

회사 문서 하나 = **세션 5개**. 단계마다 터미널로 나갔다가 새로 들어옵니다.

| 단계 | 터미널에서 실행 | 대화창에 입력 | 나오는 것 |
|---|---|---|---|
| **1** | `MAX_THINKING_TOKENS=4000 claude` | `<회사명>(<티커>) 문서 만들어줘` | 폴더 + `04_metrics.md` |
| **2** | `MAX_THINKING_TOKENS=2000 claude` | `<회사명> 2단계 진행해줘` | `.work/<company>/facts.md` (정성 조사) |
| **3** | `MAX_THINKING_TOKENS=2000 claude` | `<회사명> 3단계 진행해줘` | `01`·`02`·`03`·`05`·`08` |
| **4** | `claude` ← 상한 없음 | `<회사명> 4단계 진행해줘` | `06`(밸류에이션)·`07`(투자 판단) |
| **5** | `MAX_THINKING_TOKENS=2000 claude` | `<회사명> 5단계 진행해줘` | `09`·`10`(차트)·`11` + 마무리 검증 |

각 단계가 끝나면 에이전트가 **다음 단계의 실행 명령을 그대로 알려줍니다.** 그 줄만 복사해서 쓰면 됩니다.

---

## 지키면 되는 것 세 가지

1. **단계 사이에는 `Ctrl+D`로 세션을 완전히 끝내고 다시 실행합니다.** `/clear`는 안 됩니다 — 같은 프로세스라 `MAX_THINKING_TOKENS`가 그대로 남아 다음 단계에 잘못된 상한이 걸립니다.
2. **실행 명령 앞의 `MAX_THINKING_TOKENS=…`를 빼먹지 않습니다.** 안 붙이면 기본값 31,999가 걸려 그 세션이 비싸집니다. **4단계만 일부러 붙이지 않습니다** (밸류에이션 방법론 채택·Bear Case 판정에 실제로 사고가 필요해서).
3. **커밋은 내가 말해야 합니다.** 5단계까지 끝나도 에이전트는 파일 저장까지만 합니다.

---

## 시작할 때 — 첫 마디

**신규 작성**

```
<회사명>(<티커>) 문서 만들어줘. 섹터는 <sector 폴더명>.
```

섹터를 몰라도 됩니다. 안 적으면 에이전트가 기존 `docs/sectors/` 목록을 보고 제안합니다.

**이미 있는 회사 손보기** — "개선/업데이트/최신화"도 전부 같은 스킬입니다. 부분 수정이 아니라 **폴더를 지우고 다시 만드는 방식**이라 1단계부터 시작합니다.

```
<회사명> 문서 최신화해줘
```

지우기 전에 웹에서 다시 못 구하는 것(뉴스 로그, 회사 고유 `!!! warning`, 섹터 합의 지표, 방법론 채택 사유)은 에이전트가 `.work/<company>/carryover.md`로 옮겨두고, 5단계에서 반영 여부를 확인합니다.

---

## 지금 몇 단계인지 모를 때

그냥 물어봐도 됩니다 — `<회사명> 지금 몇 단계까지 됐는지 봐줘`. 에이전트가 아래 명령으로 판정합니다.

```bash
D=docs/sectors/<sector>/<company>
grep -l '^> ⚠️' $D/*.md 2>/dev/null | sed 's#.*/##' | tr '\n' ' '; echo; ls .work/<company>/facts.md 2>/dev/null || echo "facts.md 없음"
```

- 폴더가 없거나 전부 걸림 → **1단계**
- `04`만 빠졌고 `facts.md` 없음 → **2단계**
- `facts.md` 있고 `01`·`02`·`03`·`05`·`08`이 걸림 → **3단계**
- `06`·`07`만 남음 → **4단계**
- `09`·`10`·`11`만 걸림 → **5단계**
- 아무것도 안 걸림 → 완료

`> ⚠️`(템플릿 지침 블록)가 남아 있으면 아직 안 채운 파일이라는 뜻입니다.

## 자주 헷갈리는 것

**Q. 그냥 한 대화에서 5단계까지 이어서 하면 안 되나요?**
됩니다만 비쌉니다. 대화가 길어질수록 매 턴 전체 컨텍스트가 다시 실려서 **비용이 제곱으로 붙습니다.** 실측(EQT)에서 1단계 대화를 안 비우고 2단계를 이어갔더니 같은 범위에 **37% 더 들었습니다.** 그래서 에이전트는 앞 단계 흔적이 있는 대화에서 다음 단계를 요청받으면 일단 멈추고 알려줍니다. 그래도 이어서 하라고 하면 진행합니다.

**Q. 세션이 중간에 죽었습니다.**
그 단계만 다시 하면 됩니다. 인수인계는 대화가 아니라 **디스크에 쓰인 파일**(`04_metrics.md`, `.work/<company>/facts.md`)로 하기 때문에 앞 단계 결과는 남아 있습니다. 위 판정 명령으로 시작 지점을 정합니다.

**Q. 왜 4단계만 사고 상한을 안 거나요?**
`06`·`07`이 이 작업에서 유일하게 진짜 판단이 필요한 구간이라서입니다 — 어떤 밸류에이션 방법론을 쓰고 뺄지, Bear Case에 트리거·하방 밸류에이션·확인/기각 신호 셋이 다 있는지. 나머지는 조사 결과를 정해진 틀에 옮기는 작업이라 상한을 걸어도 품질이 안 떨어집니다.

**Q. `settings.json`에 `MAX_THINKING_TOKENS`를 넣어두면 편하지 않나요?**
안 됩니다. 프로젝트 전역으로 걸리면 4단계까지 같이 깎이고, `ultrathink`·`think hard` 키워드가 조용히 무시됩니다. **실행 명령 앞에 붙여야** 그 세션에만 적용됩니다.

**Q. `.work/` 폴더는 뭔가요?**
단계 간 인수인계용 임시 파일입니다(`carryover.md`·`facts_sec.md`·`facts.md`·차트 산출물). `.gitignore` 대상이라 저장소에는 안 들어가고, 5단계가 끝나면 지워도 됩니다.

**Q. 조금만 고치면 되는데 왜 폴더를 통째로 지우나요?**
부분 수정하면 눈에 띄는 절만 고치고 옛 구조가 그대로 남기 때문입니다. 재생성하면 구조가 항상 최신 템플릿이고 모든 수치를 다시 검증하게 됩니다. 지운 내용은 git 히스토리에 남습니다.

```

```
