# `create-company-doc` 사용법 (저장소 주인용)

같은 폴더의 [`SKILL.md`](./SKILL.md)는 **에이전트가 읽는 절차서**입니다. 이 문서는 그중 **내가 터미널에서 무엇을 치고 대화창에 뭐라고 말하는지**만 뽑은 것입니다. 규칙이 어긋나면 `SKILL.md`가 우선입니다.

---

## 한 장 요약

회사 문서 하나 = **세션 하나**. 터미널에서 `claude` 한 번 띄우고, 한 대화에서 끝까지 갑니다.

```
claude
```

```
<회사명>(<티커>) 문서 만들어줘. 섹터는 <sector 폴더명>.
```

에이전트가 아래 순서로 진행하고, 마지막에 검증 결과를 보고합니다.

| 순서 | 나오는 것 |
|---|---|
| 1 | 폴더 준비 (기존 폴더가 있으면 옮길 것 추출 → 템플릿 복사) |
| 2 | `04_metrics.md` (SEC XBRL 스크립트 + 시장 데이터) |
| 3 | 정성 조사 → `01`·`02`·`03`·`05`·`08` |
| 4 | `06`(밸류에이션)·`07`(투자 판단) |
| 5 | `09`·`10`(차트)·`11` + 마무리 검증 |

**중간에 세션을 끊지 않습니다.** 예전에는 다섯 세션으로 쪼갰지만 폐기했습니다 — 아래 "자주 헷갈리는 것" 참고.

---

## 지키면 되는 것 두 가지

1. **한 대화에서 끝까지 갑니다.** 중간에 `/clear`하거나 Ctrl+D로 나가지 않습니다 — 인수인계가 끊기면 에이전트가 이미 만든 문서를 다시 읽어야 해서 오히려 비싸집니다.
2. **커밋은 내가 말해야 합니다.** 다 끝나도 에이전트는 파일 저장까지만 합니다.

---

## 시작할 때 — 첫 마디

**신규 작성**

```
<회사명>(<티커>) 문서 만들어줘. 섹터는 <sector 폴더명>.
```

섹터를 몰라도 됩니다. 안 적으면 에이전트가 기존 `docs/sectors/` 목록을 보고 제안합니다.

**이미 있는 회사 손보기** — "개선/업데이트/최신화"도 전부 같은 스킬입니다. 부분 수정이 아니라 **폴더를 지우고 다시 만드는 방식**입니다.

```
<회사명> 문서 최신화해줘
```

지우기 전에 웹에서 다시 못 구하는 것(뉴스 로그, 회사 고유 `!!! warning`, 섹터 합의 지표, 방법론 채택 사유)은 에이전트가 `.work/<company>/carryover.md`로 옮겨두고, 마지막 검증에서 반영 여부를 확인합니다.

## 세션이 중간에 죽었을 때

처음부터 다시 할 필요 없습니다. 새로 `claude`를 띄우고 이렇게 말하면 됩니다.

```
<회사명> 문서 어디까지 됐는지 보고 이어서 마저 만들어줘
```

인수인계는 대화가 아니라 **디스크에 쓰인 파일**로 하기 때문에 이미 채운 문서는 남아 있습니다. 에이전트는 아래 명령으로 남은 일을 판정합니다.

```bash
grep -l '^> ⚠️' docs/sectors/<sector>/<company>/*.md 2>/dev/null | sed 's#.*/##' | tr '\n' ' '
```

`> ⚠️`(템플릿 지침 블록)가 남아 있으면 아직 안 채운 파일이라는 뜻입니다.

## 자주 헷갈리는 것

**Q. 예전엔 5단계로 쪼갰잖아요. 왜 없앴나요?**
Rocket Lab을 5단계로 만들었는데도 **5시간 한도의 80% 이상**을 썼습니다. 세션당 컨텍스트를 낮추는 효과 자체는 있었지만, 세션을 새로 열 때마다 시스템 프롬프트·`AGENTS.md`·툴 스키마·앞 단계 산출물을 다시 적재하는 비용이 절감분을 상당 부분 되먹었고, 터미널을 5번 왕복하는 번거로움은 그대로였습니다. 그래서 한 세션 일괄로 되돌렸습니다.

**Q. 그럼 이제 토큰은 어떻게 아끼나요?**
**턴 수**로 아낍니다. 턴 하나가 그 시점 컨텍스트 전체를 다시 실어 나르기 때문에, 서로 안 기다려도 되는 도구 호출(웹 검색 4~5개, 파일 읽기, 문서 5개 쓰기, 검증 명령)을 **한 턴에 몰아서** 내는 게 가장 큰 절감입니다. 실측에서 도구 51번을 52턴에 나눠 낸 세션이 있었는데, 그게 그 세션이 비쌌던 주된 이유였습니다. 조사 원문과 차트 SVG를 대화로 통과시키지 않고 `.work/`에 파일로 내리는 것도 같은 이유입니다.

**Q. `MAX_THINKING_TOKENS`를 걸면 더 싸지지 않나요?**
싸지긴 합니다(실측 −11~−33%). 다만 밸류에이션 방법론 채택·Bear Case 판정에서 품질이 떨어질 수 있어 기본값으로는 걸지 않습니다. 정말 급하게 초안만 뽑고 싶으면 `MAX_THINKING_TOKENS=2000 claude`로 띄우되, `06`·`07`은 나중에 다시 보는 걸 전제하세요. **`settings.json`의 `env`에는 넣지 마세요** — 프로젝트 전역으로 걸리면 `ultrathink`·`think hard` 키워드가 조용히 무시됩니다([claude-code#18072](https://github.com/anthropics/claude-code/issues/18072)).

**Q. `.work/` 폴더는 뭔가요?**
작업 중 임시 파일입니다(`carryover.md`·`facts_sec.md`·차트 산출물). 조사 원문·스크립트 출력을 대화에 싣지 않으려고 여기로 내립니다. `.gitignore` 대상이라 저장소에는 안 들어가고, 작업이 끝나면 지워도 됩니다.

**Q. 조금만 고치면 되는데 왜 폴더를 통째로 지우나요?**
부분 수정하면 눈에 띄는 절만 고치고 옛 구조가 그대로 남기 때문입니다. 재생성하면 구조가 항상 최신 템플릿이고 모든 수치를 다시 검증하게 됩니다. 지운 내용은 git 히스토리에 남습니다.
