# 회사 문서 템플릿 전면 갱신

## 언제 쓰나

- 대상: 이미 존재하는 `docs/sectors/<sector>/<company>/` 폴더
- 트리거 예시: "이 회사 문서 개선해", "템플릿 기준으로 업데이트해", "이 회사 문서 다시 손봐줘", "최신 템플릿 반영해줘"
- **대상 아님**:
  - 새 회사 폴더를 처음 만드는 작업 → `authoring-guide.md`의 "새 회사/섹터 추가 방법"대로 템플릿을 복사하면 끝. 이 스킬 불필요.
  - `docs/index.md`·`AGENTS.md` 자체에 대한 개선 요청 → `review-master-docs` 스킬 대상.

## 왜 필요한가

"개선해"라는 지시만 받으면 눈에 밟히는 문제 한두 개만 고치고 끝내기 쉽다. 하지만 `docs/meta/.template/company/`는 시간이 지나며 구조가 바뀐다 — 예를 들어 `11_final_report.md`는 나중에 추가된 파일이라, 그 전에 만들어진 회사 폴더는 이 파일 자체가 통째로 빠져 있어도 눈에 띄지 않는다. 이 스킬은 "지적받은 부분만 고치는 것"이 아니라 **템플릿 전체 구조 대비 회사 폴더 전체를 의무적으로 훑게** 만들어서, 이런 누락이 조용히 방치되지 않게 한다.

## 절차

1. **대상 회사 폴더 확정** — `docs/sectors/<sector>/<company>/`. 사용자가 회사명만 말했으면 `docs/sectors/`에서 실제 경로를 찾는다.
2. **템플릿 전체를 읽는다** — `docs/meta/.template/company/`의 파일 11개 전부. 각 파일의 섹션(`##`) 구성, 안내 각주(⚠️ 표기), placeholder를 파악한다. 필요하면 `git log --oneline -- docs/meta/.template/company/`로 최근에 추가·변경된 규칙이 있는지 확인한다 — 회사 폴더가 그 변경 이전에 만들어졌으면 못 따라갔을 가능성이 높다.
3. **회사 폴더 안의 파일을 전부 읽는다** — 존재하는 파일 전체. 일부만 보고 판단하지 않는다.
4. **파일·절 단위 갭 목록을 작성한다**:
   - 템플릿에는 있는데 회사 폴더에 없는 **파일** — 필수(`01_overview.md`)인지 선택인지 구분해서 후보로 남긴다. 선택 파일이 빠진 게 의도적인지(예: "단순한 사업이라 C절 삭제"처럼 사유가 문서에 남아 있는지) 확인한다. `11_final_report.md`가 없다면 01~10이 이미 갖춰진 폴더인지 먼저 확인 — 갖춰졌다면 이 스킬의 마지막 단계(6번)에서 새로 만든다.
   - 존재하는 파일 안에서, 템플릿에는 있는데 회사 문서엔 없는 **절**
   - 템플릿의 경고·규칙 각주(GAAP/Non-GAAP 구분, 부채총계 vs 이자부 차입금, 적용 여부 판단 기준 등)가 실제로 지켜졌는지
   - `AGENTS.md` "초안을 받으면 먼저 훑는 것"의 다섯 가지 숫자 규칙(할인율·현금흐름 짝 / GAAP 구분 / 부채총계 vs 이자부 차입금 / 평균·중앙값에 (E) 혼입 / 주식분할 소급조정) 위반 여부
   - Bear Case 3요소(트리거 / 하방 밸류에이션 결과 / 확인·기각 신호) 중 빠진 게 있는지
   - `04_metrics.md` 값과 `05`·`06`·`07`·`09`·`10`(종가 겹칠 때)·`11`(있다면)이 실제로 일치하는지 — grep으로 값을 대조한다(추측 금지). `11_final_report.md`가 이미 있다면 이번에 01~10을 고친 내용이 반영됐는지가 가장 흔한 갭이다.
   - 남아 있는 placeholder(`<회사명>`, `<TICKER>` 등)나 미완성 표
   - `*작성일*`이 문서 안 최신 데이터 시점과 맞는지
5. **갭 목록을 먼저 사용자에게 보여준다** — 무엇이 왜 빠졌거나 틀렸고, 고치면 결론(적정주가·투자 판단)이 달라지는지. `AGENTS.md`의 "틀린 걸 발견하면 조용히 고치지 않는다" 원칙대로, 이유 없이 바로 덮어쓰지 않는다.
6. **목록 기준으로 실제 파일을 갱신한다** — 빠진 파일은 템플릿을 복사해 채우고, 기존 파일은 절 단위로 보완한다. 수치는 `AGENTS.md` "수치는 확인 후 기입한다" 원칙대로 최신 출처로 검증하고, 확인 못 하면 (E) + 출처 각주로 남긴다.
   `01~10`을 하나라도 고쳤다면 `11_final_report.md`(있는 경우)를 가장 마지막에 다시 확인한다 — 이 문서는 새 숫자를 만들지 않고 01~10을 인용만 하므로(`authoring-guide.md` "`11_final_report.md` 작성 규칙"), 원 문서가 바뀌면 그 인용도 바뀌어야 한다. 01~10은 갖춰져 있는데 `11_final_report.md`가 아예 없다면(과거에 만든 폴더) 이번에 새로 만든다.
7. **마무리 체크리스트** — `AGENTS.md` "작업을 마치기 전에" 5개 항목을 실제로 수행한다: 고친 숫자의 인용처 grep 추적(`11_final_report.md` 포함), `*작성일*`(있으면 최종 수정일) 갱신, 새 섹터라면 `.pages` 등록, `uv run mkdocs build`로 깨진 링크 확인, 확인 못 한 값이 확정치처럼 남아있지 않은지. 더해서 `grep -rn "> ⚠️" docs/sectors/<sector>/<company>/`로 **템플릿 지침 블록이 남아 있지 않은지** 확인한다 — 규칙은 `authoring-guide.md` "표기법이 곧 발행 여부를 뜻한다"가 마스터이고, 템플릿 안에는 더 이상 이 설명이 없다.

## 하지 않는 것

- 이미 맞는 내용을 문체만 다듬는 재작성 (스코프 아님 — 숫자·구조·근거의 정합성만 본다)
- 회사 문서 안에서 새 용어를 정의하는 것 — 없는 개념이 필요하면 `glossary.md`·`concepts/`를 먼저 갱신
- 커밋·푸시 — `AGENTS.md` 커밋 정책대로 사용자가 명시적으로 요청할 때만

## 참고

- 회사 템플릿 자체의 마스터 규칙은 `authoring-guide.md`(폴더·파일 구조·작성 규칙), 리뷰 관점(숫자 검증·방법론 적용 여부·Bear Case 판정)은 `AGENTS.md`에 있다 — 이 스킬은 그 둘을 "회사 폴더 전체 대상으로 빠짐없이" 적용하는 절차일 뿐, 새 기준을 만들지 않는다.
