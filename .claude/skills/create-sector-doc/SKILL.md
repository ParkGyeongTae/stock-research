# 섹터 개요 문서 신규 작성

## 언제 쓰나

- 대상: `docs/sectors/<sector>/00_overview.md`가 아직 없는 섹터. 완전히 새로운 섹터일 수도 있고, 이미 회사 폴더는 있지만 산업 자체를 설명하는 문서가 빠진 기존 섹터일 수도 있다.
- 트리거 예시: "<섹터명> 개요 문서 만들어줘", "이 섹터 산업 설명부터 써줘", "<섹터명> 커버리지 시작하니 섹터 개요도 추가해줘"
- **대상 아님**:
  - 이미 있는 `00_overview.md`를 갱신하는 작업 → `improve-sector-doc` 대상
  - 회사 문서 신규 작성 → `create-company-doc` 대상 (신규 섹터에서 첫 회사를 추가하는 상황이면 두 스킬을 함께 쓴다 — 아래 "참고" 참조)
  - `docs/index.md`·`AGENTS.md` 자체 개선 → `review-master-docs` 대상

## 왜 필요한가

섹터 개요는 회사 문서와 성격이 다르다 — 특정 회사의 사실이 아니라 산업 전체의 구조·성장 동력·리스크를 다루므로, 회사 문서 작성 습관 그대로 옮기면 스코프가 흐려지기 쉽다(예: 특정 회사 실적을 "산업 성장 동력"으로 적거나, 개별 회사 리스크를 "구조적 리스크"로 뭉뚱그리는 식). 이 스킬은 `docs/meta/.template/sector/00_overview.md`가 정한 스코프(산업 자체만, 회사별 사실·투자 판단은 각 회사 문서로)를 지키면서 채우게 한다.

## 절차

1. **섹터 폴더 상태 확인**
   - `docs/sectors/<sector>/`가 이미 있는지 확인한다. 없으면 완전히 새로운 섹터 — 섹터 폴더명은 풀어 쓴 소문자 스네이크케이스(예: `electronic_design_automation`)로 정한다.
   - 있으면(회사 폴더는 이미 있는데 `00_overview.md`만 없는 경우) 폴더는 그대로 두고 `00_overview.md`만 추가한다.

2. **템플릿 복사**
   명령은 `authoring-guide.md` "➕ 새 회사 / 새 섹터 추가 방법"의 4번 그대로 따른다.
   폴더 자체가 새로 생긴 경우에만 `docs/sectors/.pages`의 `nav:`에 폴더명을 추가한다(등록 안 해도 빌드는 성공하지만 내비게이션에서 조용히 빠진다 — 경고 없음). 기존 섹터에 `00_overview.md`만 추가하는 경우는 이미 등록돼 있으므로 불필요.

3. **콘텐츠를 산업 스코프 안에서 채운다** (템플릿의 절 순서대로)
   - **밸류체인**("산업 구조 — 돈이 어떻게 도는가" 절): 원재료/기술 → 제품·서비스 → 최종 수요 단계별로, 이 섹터의 커버리지 기업들이 어느 단계에 있는지. 개별 회사의 구체적 진입장벽은 각 회사 `07_investment.md`로 넘긴다.
   - **시장 규모/성장 동력**("시장 규모 / 성장 동력" 절): TAM·CAGR은 출처와 기준 연도를 반드시 병기한다. 리서치 기관마다 정의(포함 범위)가 달라 값이 갈리면 하나로 단정하지 말고 범위로 남긴다. 특정 회사의 실적 가이던스를 "산업 성장 동력"으로 적지 않는다 — 그건 회사 고유의 것이다.
   - **구조적 리스크**("구조적 리스크 / 경기 민감도" 절): 섹터 안 회사 대부분이 공통으로 노출되는 리스크만 남긴다(경기 사이클, 규제, 원자재·투입 비용, 기술 대체). 특정 회사만의 리스크는 그 회사 `07_investment.md` Bear Case로 넘긴다.
   - **체크할 지표**("이 섹터를 볼 때 체크하는 지표 / 신호" 절): 회사 실적 발표 전에 참고할 선행지표·매크로 변수(산업지수, 정책 예산, 규제 일정 등).
   - 수치는 기억으로 단정하지 않는다. WebFetch/WebSearch로 확인하고, 출처 우선순위는 1차 자료(정부·업계 통계, 규제기관 발표) > 리서치 기관 리포트 > 언론 순.

4. **커버리지 기업·인접 섹터 링크를 채운다**
   - 상단 메타 블록의 "커버리지 기업"에 이 섹터의 모든 회사 폴더를 링크한다.

5. **회사 문서 쪽 역참조를 확인한다**
   - 이 섹터에 이미 회사 문서가 있다면, 각 회사의 `01_overview.md` "산업 / 시장 내 위치" 절이 새로 만든 `00_overview.md`를 링크하고 있는지 확인한다(회사 템플릿에는 이미 이 안내가 있지만, 오래전에 만든 회사 폴더는 템플릿이 갱신되기 전에 복사됐을 수 있다). 안 돼 있으면 링크를 추가한다.

6. **마무리 체크리스트**
   - **템플릿에서 온 `> ⚠️` 작성자 지침 블록이 하나도 남지 않았는지** — `grep -n "> ⚠️" docs/sectors/<sector>/00_overview.md`로 확인한다. 규칙은 `authoring-guide.md` "표기법이 곧 발행 여부를 뜻한다"가 마스터다(템플릿 안에는 더 이상 이 설명이 없다). `!!! …`·`??? …`는 독자용이니 실제 내용으로 채워 남긴다
   - `*작성일*` 표기 — 오늘 날짜는 세션 컨텍스트 `# currentDate` → `date +%Y-%m-%d` → 확인 불가 시 사용자에게 확인
   - 신규 섹터 폴더였다면 `docs/sectors/.pages` 등록을 실제로 했는지 재확인
   - `uv run mkdocs build`로 깨진 링크(`unrecognized relative link`) 없는지 확인
   - 확인 못 한 TAM·CAGR 등은 확정치처럼 남기지 않고 출처·범위를 함께 남겼는지

## 하지 않는 것

- 특정 회사의 재무 수치·투자 판단을 이 문서에 적는 것 — 각 회사 문서로 넘긴다
- 회사 간 배수 비교·순위 매기기 — 이 문서의 역할이 아니다
- 새 용어를 이 문서에서 정의하는 것 — 없는 개념이 필요하면 `glossary.md`·`concepts/`를 먼저 갱신
- 커밋·푸시 — `AGENTS.md` 커밋 정책대로 사용자가 명시적으로 요청할 때만

## 참고

- 완전히 새로운 섹터에서 첫 회사를 동시에 추가하는 상황이면 `create-company-doc`과 이 스킬을 함께 쓴다 — 순서는 상관없지만, 회사 문서 "산업 / 시장 내 위치" 절에서 `00_overview.md`를 링크하려면 이 스킬로 그 파일을 먼저 만들어두는 편이 자연스럽다.
- 문서 스코프·형식의 마스터는 `docs/meta/.template/sector/00_overview.md`와 `authoring-guide.md`다 — 이 스킬은 그 스코프를 신규 작성 흐름에서 지키게 할 뿐, 새 기준을 만들지 않는다.
