# 섹터 개요 작성 (신규 · 재생성 공통)

## 언제 쓰나

- 신규: "<섹터명> 개요 문서 만들어줘", "이 섹터 산업 설명부터 써줘"
- 재생성: "<섹터명> 개요 개선해줘 / 최신화해줘"
- **대상 아님**: 회사 문서 → `create-company-doc` · 거시지표 → `create-macro-doc` · 마스터 문서 검토 → `review-master-docs`

## 왜 이렇게 하나

섹터 개요는 회사 문서와 성격이 다르다 — 특정 회사의 사실이 아니라 산업 전체의 구조·성장 동력·리스크를 다루므로, 회사 문서 습관 그대로 쓰면 스코프가 흐려진다(특정 회사 실적을 "산업 성장 동력"으로 적거나, 개별 회사 리스크를 "구조적 리스크"로 뭉뚱그리는 식). 부분 수정하면 낡은 시장 데이터와 새 서술이 뒤섞이므로 **개선 요청도 재생성으로 처리한다** — 지운 내용은 git 히스토리에 남는다.

## 절차

### 1. 파일 삭제 후 템플릿 복사

```bash
rm -f docs/sectors/<sector>/00_overview.md
cp docs/meta/.template/sector/00_overview.md docs/sectors/<sector>/00_overview.md
```

재생성이면 지우기 전에 **TAM·CAGR의 출처와 기준 연도**를 메모해 둔다 — 어느 리서치 기관 값이었는지 알아야 새로 조사한 값과 비교가 된다.

섹터 폴더 자체가 새로 생긴 경우에만 `docs/sectors/.pages`의 `nav:`에 폴더명을 추가한다(안 하면 경고 없이 내비게이션에서 빠진다). 기존 섹터에 개요만 추가·재생성하는 경우는 이미 등록돼 있다.

### 2. 산업 스코프 안에서 채운다 (템플릿 절 순서대로)

- **"산업 구조 — 돈이 어떻게 도는가"**: 원재료/기술 → 제품·서비스 → 최종 수요 단계별로, 커버리지 기업들이 어느 단계에 있는지. 개별 회사의 구체적 진입장벽은 그 회사 투자 판단 문서로 넘긴다.
- **"시장 규모 / 성장 동력"**: TAM·CAGR은 **출처와 기준 연도를 반드시 병기.** 리서치 기관마다 포함 범위가 달라 값이 갈리면 하나로 단정하지 말고 범위로 남긴다. 특정 회사의 실적 가이던스를 산업 성장 동력으로 적지 않는다.
- **"구조적 리스크 / 경기 민감도"**: 섹터 안 회사 대부분이 공통으로 노출되는 것만(경기 사이클, 규제, 원자재·투입 비용, 기술 대체). 특정 회사만의 리스크는 그 회사 Bear Case로 넘긴다.
- **"이 섹터를 볼 때 체크하는 지표 / 신호"**: 회사 실적 발표 전에 참고할 선행지표·매크로 변수. 실제로 걸리는 macro 문서가 있으면 `.md` 파일을 직접 링크한다.
- 수치는 기억으로 단정하지 않는다. 출처 우선순위는 1차 자료(정부·업계 통계, 규제기관 발표) > 리서치 기관 리포트 > 언론.

### 3. 회사 문서 쪽 역참조 확인

이 섹터에 회사 문서가 있으면, 각 회사 개요의 "산업 / 시장 내 위치" 절이 이 문서를 링크하고 있는지 확인한다. 안 돼 있으면 추가한다.

### 4. 마무리 체크리스트

- **`> ⚠️` 지침 블록이 남지 않았는지** — `grep -n "> ⚠️" docs/sectors/<sector>/00_overview.md`가 비어야 한다. `!!! …`·`??? …`는 독자용이니 실제 내용으로 채워 남긴다
- `*작성일*` — 오늘 날짜는 `# currentDate` → `date +%Y-%m-%d` → 확인 불가 시 사용자에게 확인
- 신규 섹터 폴더였다면 `.pages` 등록 재확인
- `uv run mkdocs build`로 `unrecognized relative link` 없는지 확인
- TAM·CAGR이 확정치처럼 남지 않고 출처·범위와 함께 적혔는지

## 하지 않는 것

- 특정 회사의 재무 수치·투자 판단을 이 문서에 적는 것 — 각 회사 문서로 넘긴다
- 회사 간 배수 비교·순위 매기기 — 이 문서의 역할이 아니다
- 새 용어를 이 문서에서 정의하는 것 — `glossary.md`·`concepts/`를 먼저 갱신
- 커밋·푸시 — 사용자가 명시적으로 요청할 때만

## 참고

새 섹터에서 첫 회사를 동시에 추가하는 상황이면 `create-company-doc`과 함께 쓴다 — 회사 문서가 이 개요를 링크하므로 이 파일을 먼저 만들어두는 편이 자연스럽다. 스코프·형식의 마스터는 `docs/meta/.template/sector/00_overview.md`와 `authoring-guide.md`다.
