# 섹터 개요 문서 전면 갱신

## 언제 쓰나

- 대상: 이미 존재하는 `docs/sectors/<sector>/00_overview.md`
- 트리거 예시: "이 섹터 개요 업데이트해줘", "00_overview.md 최신화해줘", "이 섹터 문서 다시 손봐줘"
- **대상 아님**:
  - `00_overview.md`가 아직 없는 섹터에 처음 만드는 작업 → `create-sector-doc` 대상
  - 회사 문서 개선 → `improve-company-doc` 대상
  - `docs/index.md`·`AGENTS.md` 자체 개선 → `review-master-docs` 대상

## 왜 필요한가

섹터 개요는 회사 문서보다 갱신 빈도가 낮아서 방치되기 쉽다 — 새 회사가 섹터에 추가돼도 `00_overview.md`의 "커버리지 기업" 목록이 안 따라오거나, TAM·CAGR 수치가 몇 분기 전 출처 그대로 남는 식이다. 또 회사 문서 쪽에서 산업 설명을 다시 길게 쓰면서 `00_overview.md`와 내용이 겹치는 경우도 있다. "개선해"라는 지시만으로는 이런 구조적 누락이 눈에 안 띄기 쉬우므로, 이 스킬은 섹터 문서와 소속 회사 문서 전체를 강제로 대조하게 한다.

## 절차

1. **대상 섹터 폴더 확정** — `docs/sectors/<sector>/`
2. **템플릿을 읽는다** — `docs/meta/.template/sector/00_overview.md`의 절 구성·경고 각주를 파악한다. 필요하면 `git log --oneline -- docs/meta/.template/sector/`로 템플릿이 그 섹터 문서 작성 이후 바뀌었는지 확인한다.
3. **섹터 폴더 안 문서와 소속 회사 폴더를 전부 읽는다**
   - `00_overview.md` 전체
   - `docs/sectors/<sector>/` 아래 모든 회사 폴더의 `01_overview.md`(최소한 3. 산업 / 시장 내 위치), `04_metrics.md`
4. **갭 목록을 작성한다**
   - 템플릿에는 있는데 `00_overview.md`엔 없는 절, 또는 남아 있는 placeholder(`<섹터명>`, `<company-1>` 등)
   - **커버리지 기업 목록 불일치** — 실제 `docs/sectors/<sector>/` 아래 회사 폴더와 `00_overview.md` 상단 목록이 다른지(새 회사가 추가됐는데 반영 안 됨, 반대로 폴더가 없어졌는데 링크만 남음)
   - TAM·CAGR 등 시장 수치의 출처·기준 연도가 오래됐는지(작성일 대비 몇 분기·몇 년 지났는지)
   - **스코프 중복** — 회사 `01_overview.md` 3. 산업 / 시장 내 위치나 `05_financials.md`가 산업 전체 설명(밸류체인·시장 규모)을 다시 길게 서술하고 있어 `00_overview.md`와 내용이 겹치는지. 겹치면 회사 문서 쪽을 줄이고 링크로 대체한다.
   - 회사 `01_overview.md` 3. 산업 / 시장 내 위치가 `00_overview.md`를 링크하고 있는지(오래전에 만든 회사 폴더는 이 안내가 추가되기 전 템플릿을 복사했을 수 있음)
   - `*작성일*`이 실제 최신 데이터 시점과 맞는지
5. **갭 목록을 먼저 사용자에게 보여준다** — 무엇이 왜 낡았거나 어긋났는지. `AGENTS.md`의 "틀린 걸 발견하면 조용히 고치지 않는다" 원칙대로, 이유 없이 바로 덮어쓰지 않는다.
6. **목록 기준으로 실제 파일을 갱신한다** — 절 단위로 보완하고, 회사 문서와 중복된 내용은 한쪽으로 정리한다(산업 전체는 `00_overview.md`, 회사 관점은 회사 문서).
7. **마무리 체크리스트**
   - `*작성일*` 갱신
   - 고친 시장 수치를 인용하는 다른 문서가 있으면(드물지만 회사 문서가 섹터 성장률을 인용했다면) 함께 확인
   - `uv run mkdocs build`로 깨진 링크 확인
   - 확인 못 한 값이 확정치처럼 남아 있지 않은지

## 하지 않는 것

- 이미 맞는 내용을 문체만 다듬는 재작성 (스코프 아님)
- 회사별 재무 수치·투자 판단을 이 문서에 채우는 것 — 회사 문서로 넘긴다
- 회사 간 배수 비교·순위를 이 문서에 채우는 것 — 이 문서의 역할이 아니다
- 새 용어를 이 문서에서 정의하는 것 — 없는 개념이 필요하면 `glossary.md`·`concepts/`를 먼저 갱신
- 커밋·푸시 — `AGENTS.md` 커밋 정책대로 사용자가 명시적으로 요청할 때만

## 참고

- 섹터 문서의 스코프·형식 마스터는 `docs/meta/.template/sector/00_overview.md`와 `authoring-guide.md`(폴더·파일 구조·작성 규칙), 리뷰 관점은 `AGENTS.md`다 — 이 스킬은 그 규칙들을 섹터 문서 전체 대상으로 빠짐없이 적용하는 절차일 뿐, 새 기준을 만들지 않는다.
