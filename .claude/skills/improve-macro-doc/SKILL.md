# 거시지표 참고 문서 갱신

## 언제 쓰나

- 대상: 이미 존재하는 `docs/meta/macro/{foreign_exchange,rates,bonds,equities,metals,energy,cryptocurrency}/*.md`
- 트리거 예시: "금 차트 최신 데이터로 갱신해줘", "commodities 문서들 이번 분기 갱신 돌려줘", "이 macro 문서 손봐줘"
- **대상 아님**: 아직 없는 새 자산 추가 → `create-macro-doc`

## 왜 필요한가

"갱신해줘"라는 지시만 받으면 1. 차트 — 최근 5년 주봉만 다시 그리고 끝내기 쉽다. 하지만 스크립트가 만드는 건 1. 차트 — 최근 5년 주봉의 기계적 산출물뿐이라, 2. 해석·관련 문서 링크·작성일 표기는 사람이 따로 손대야 하고 잊기 쉽다. 이 스킬은 "차트만 갱신"이 아니라 문서 전체를 훑게 강제한다.

> macro 문서는 1. 차트 — 최근 5년 주봉 → 2. 해석 → 관련 문서 → 참고 자료만 남기는 것으로 스코프를 좁혔다(2026-08-20 3. 지지선 / 저항선 요약·4. 방법론 · 한계 제거, 2026-08-21 "갱신 방법" 절도 제거하고 재생성 커맨드를 `chart-generation-guide.md`(당시엔 `authoring-guide.md` 안) "macro 문서 재현 파라미터" 표로 통합, 전체 27개 문서에 적용 완료). 혹시 이 구조를 벗어난(3. 지지선 / 저항선 요약·4. 방법론 · 한계나 "## 갱신 방법"이 남아 있는) 문서를 발견하면 — 예를 들어 이 스킬 없이 손으로 만들어졌거나 과거 기록에서 복원된 경우 — 아래 5번대로 통째로 걷어내 새 구조에 맞춘다.

## 절차

1. **대상 파일 확정** — 사용자가 지표명만 말했으면 `docs/meta/macro/`에서 실제 경로를 찾는다. 여러 개("commodities 전체", "macro 전부")면 해당 범위의 파일 전체를 대상으로 한다.

2. **재생성 커맨드는 `chart-generation-guide.md` "macro 문서 재현 파라미터" 표에서 가져온다** — 티커·옵션·조정 각주는 문서가 아니라 그 표가 단일 출처다. 표에 해당 문서 행이 없는 구세대 문서라면(과거 기록에서 복원된 경우 등) `chart-generation-guide.md` "주가가 아닌 시계열에 쓰기"를 참고해 새로 구성하고, 이번 갱신에서 표에 행을 추가한다(문서 자체에는 남기지 않는다).

3. **스크립트 재실행**
   ```bash
   uv run python scripts/gen_technical_chart.py "<TICKER>" ... --close-on <오늘 기준 최근 종가일> --emit chart
   ```
   1. 차트 — 최근 5년 주봉(차트 SVG·데이터 구간·마지막 종가)을 새 출력으로 통째로 교체한다 — 캔들 일부만 덧붙이지 않는다. 아직 3. 지지선 / 저항선 요약·4. 방법론 · 한계가 남아 있는 구세대 문서라면 이번에 그 절들을 통째로 지우므로(5번), 굳이 `table`·`facts`·`dates`까지 다시 뽑을 필요는 없다.

4. **2. 해석이 낡지 않았는지 확인**
   스크립트가 건드리지 않는 유일한 해석 절이다. 이 지표의 상승/하락 해석 자체가 바뀔 일은 거의 없지만(교과서적 관계), 이 절이 아직 없는 구세대 문서(2. 해석 없이 바로 지지선/저항선으로 넘어가는 문서)라면 이번 갱신에 맞춰 추가한다 — `docs/meta/macro/commodities/*.md` 5개가 참고 예시다.

   **시점 종속 서술이 되살아났는지도 함께 본다.** intro 블록쿼트와 2. 해석에는 수치·날짜·순위·기간을 두지 않는 것이 규칙이다(2026-08-25 전체 36개 문서에 적용) — 그런 값은 스크립트가 만드는 차트와 비교 문서의 `### 5년간 순변화 요약` 표에만 둔다. 아래가 남아 있으면 조건부 서술로 바꾼다:
   - "최근" / "최근 몇 년" / "지금" / "이 5년 동안" 같은 시점 부사
   - intro 안의 시세·수준(`달러인덱스 ~99` 등), 특정 종목명을 예로 든 구성 비중 설명
   - 5년 창 안에서만 성립하는 근거, 이번 회차에만 맞는 각주("WTI는 직전 주 종가를 쓴다")

   금지 표현 목록과 바꿔 쓰는 예시는 `chart-generation-guide.md` "macro 문서의 산문은 시점에 종속되지 않게 씁니다"가 마스터다. 비교(`comparison`) 문서 8개가 특히 재발하기 쉬우니 — 표 수치를 문장으로 옮겨 적고 싶은 충동이 크다 — 갱신할 때마다 그 절을 먼저 확인한다.

5. **구세대 구조 정리(발견 시)**
   재생성하는 김에 아래가 남아 있으면 함께 걷어낸다 — 전체 macro 문서에 이미 적용한 것과 동일한 기준이다:
   - `## 3. 지지선 / 저항선 요약`·`## 4. 방법론 · 한계` 절 전체 — 레벨 표·데이터 출처·스윙 탐지 알고리즘 설명·한계 고지를 통째로 제거한다. 지지/저항 레벨 자체는 1. 차트 — 최근 5년 주봉의 SVG에 점선으로 이미 표시되므로 정보가 완전히 사라지는 건 아니다.
   - `## 갱신 방법` 절 전체 — 재생성 커맨드는 문서에 남기지 않는다. 그 안에 있던 티커·옵션·조정 각주가 2번에서 확인한 `authoring-guide.md` 표에 아직 없으면 이번에 행으로 옮겨 적는다(정보가 사라지지 않도록).
   - intro 블록쿼트의 "커버리지 연관성" 경고 / "객관적 서술이며 투자 판단이 아니다" 면책 / 스크립트 공유 각주 3종
   - 아직 2. 해석이 없으면 4번대로 추가한다
   섹션 제거 후 남은 두 개의 "---" 구분선이 겹치지 않게(2. 해석 다음 "---"가 바로 "## 관련 문서" 앞 것과 이어지도록) 정리한다. 발견했다고 조용히 지우지 말고, 무엇을 왜 걷어내는지 먼저 말한다(`AGENTS.md` "틀린 걸 발견하면 조용히 고치지 않는다" 원칙과 같은 이유 — 저장소 주인이 판단 근거를 복기할 수 있어야 한다). 3. 지지선 / 저항선 요약·4. 방법론 · 한계·갱신 방법 제거는 데이터·재현 정보를 통째로 옮기는 것이라 보일러플레이트 제거보다 영향이 크므로, 한 문서에 먼저 적용해 보여주고 나머지에 이어가는 편이 안전하다.

6. **관련 문서·참고 자료 링크 확인** — 갱신 사이에 새로 추가된 회사·섹터 문서 중 이 지표를 인용할 만한 게 생겼으면 "관련 문서"에 추가할지 사용자에게 확인한다.

7. **마무리 체크리스트**
   - 문서 최하단 작성일 줄 갱신 — `*작성일: YYYY-MM-DD (최종 수정일: YYYY-MM-DD)*` 형식으로, 라벨은 "최종 수정일:"만 쓰고 괄호 안에 무엇을 고쳤는지는 서술하지 않는다
   - `uv run mkdocs build`로 깨진 링크(`unrecognized relative link`) 없는지 확인
   - 여러 문서를 한 번에 돌렸다면 문서 간 1. 차트 — 최근 5년 주봉의 데이터 기준일이 서로 어긋나지 않는지(같은 기준일로 맞췄는지) 확인
   - `.pages`에 이미 등록돼 있는지(신규 문서가 아니므로 보통 문제없지만, 과거 등록 누락이 함께 발견될 수 있다)
   - 3. 지지선 / 저항선 요약·4. 방법론 · 한계·갱신 방법을 걷어냈다면 문서에 `## 3.`·`## 4.`·`## 갱신 방법`·`§3`·`§4` 잔재가 없는지 grep으로 재확인하고, 그 안의 티커·옵션이 `chart-generation-guide.md` 표에 반영됐는지 확인

## 하지 않는 것

- 스윙 탐지·클러스터링 파라미터(윈도우·허용오차)를 문서마다 임의로 바꾸는 것 — 바꾸려면 전체 macro·회사 문서를 함께 재생성해야 하므로 이 스킬의 스코프 밖이다(`scripts/gen_technical_chart.py` 상단 설명 참고)
- 이미 맞는 2. 해석을 문체만 다듬는 재작성 — 내용이 틀렸거나 낡았을 때만 손댄다
- 커밋·푸시 — `AGENTS.md` 커밋 정책대로 사용자가 명시적으로 요청할 때만

## 참고

- 갱신 커맨드 문법은 `chart-generation-guide.md`, 폴더·`.pages` 규칙은 `authoring-guide.md`가 마스터다.
